# 寓+签到 — 真正独立的 macOS App（构建工程）

> **这是 macOS 自动构建工程，不是已经编译的安装包。** 需在 GitHub Actions 的 macOS 机器构建后，下载完整可运行的 `.app` 压缩包。开发者也可在 Mac 上用工作流中的命令本地构建。Linux 环境不能真正编译 Cocoa + WebKit 程序；不要将此源码 ZIP 当成已可双击运行的 App。

## 本版新增：App 内直接开启局域网访问

在最新版 App 中打开左侧 **「局域网访问」** → 开启开关 → 设置不少于 **10 位**的独立访问密码 → 保存。

- 保存后会自动重启 **Web 后台服务**，不重启每日签到调度器。正常情况下 1–3 秒后显示可用的 `http://192.168.x.x:8765` 等局域网地址，并生成可用手机扫描的二维码。
- 在相同局域网的手机上，直接扫码或访问所示地址。浏览器提示身份验证时，**用户名为 `panel`，密码是刚刚设置的访问密码**，并非寓+的账号密码。
- **Mac 上的原生 App 和 `127.0.0.1` 本地页面无需再次输入局域网密码**，不会干扰添加账号。局域网远程访客即使登录，也不能修改网络监听设置。
- 设置持久保存到系统应用数据目录内的 `network.json`，密码只储存加盐 PBKDF2 哈希，文件权限 0600，不在接口或 UI 回显。关闭 App、重启 Mac、更新 App 后会恢复设定。
- 默认关闭，关闭后 Web 服务重新绑定 `127.0.0.1`。如果地址不显示，检查 Mac 是否接入 Wi-Fi/有线网络。Mac 睡眠、断网或防火墙拦截时，手机不可访问；请在 macOS 防火墙提示里按需允许。
- **安全提醒**：此方式是普通 HTTP + Basic Auth，网络上传输的管理凭证**不经过 TLS 加密**。只适用于可信局域网，严禁公网端口映射、路由器转发端口或跨不可信热点使用。需要跨公网访问应另建 HTTPS / VPN 方案。

Debian Docker 仍兼容环境变量配置方式：`YUJIA_WEB_BIND=0.0.0.0` 和 `YUJIA_WEB_PASSWORD`。若环境变量明确配置了管理面板网络设置，界面自动显示为“由部署环境管理”的只读模式，避免面板覆盖 Docker 配置。构建增加纯 Python 的 `qrcode` 依赖，仅用于生成 SVG 二维码。

升级已存在的 macOS App：替换已编译的 `.app` 后双击打开，新版会检查并重装老的 Web LaunchAgent，让设置变更能够安全自动重启；账号和签到记录不受影响。

## 这次更新：macOS 简约管理界面 + 登录回归加固

管理页重新设计为 macOS 风格的**浅色、细边框、柔和阴影、清晰间距**布局。左侧依次为概览、账号管理、签到计划、执行记录、局域网访问、运行日志，窄窗口会自动调整为顶部导航。原本集中在一页的内容被整理成独立视图。

- 概览展示今日完成账号数、进度条、下次计划、今日异常、金币趋势及最近动态。
- 账号页面支持添加、验证、启用/停用、编辑、删除及单账号签到；添加和编辑使用统一的应用内侧边面板，避免原生 `prompt` 弹窗。
- 添加账号会自动请求区域；如网络导致区域获取失败，也能手动输入已有的 `AreaID`。业务登录失败保留输入并明确显示服务端原因。
- 计划页可以修改时间、暂停/恢复及手动执行；对于**新版 `StartInterval` launchd 方案**，改计划时不再多余地卸载、重装后台任务。SQLite 保存的时间始终优先于脚本内默认 09:05。
- 页面资源完全内嵌 Python 打包结果，不使用 CDN、在线字体或外部 JS，离线也能打开本地后台（真实签到仍需要联网）。

本次修改经 **36 项自动化测试**（包含完整 FakeAPI HTTP 模拟登录/账号保存、模拟拒绝、计划新时刻阻止旧 09:05 调度、多账号与并发保护）、前端 JS 语法检查、Python 编译检查。**未连接真实寓+生产接口，未在实机 macOS WebKit 中做视觉/交互验收**；不能据此声称真实登录或原生窗口已全部验证。

源码维护：页面源文件是 `ui/dashboard.html`，改动后执行 `python ui/sync_panel.py` 同步嵌入 `core/web_panel.py`；CI 会用 `python ui/sync_panel.py --check` 防止忘记同步。生成的 `.app` 只带内嵌界面，无需旁边的 HTML 文件。

## 修复记录：添加账号误提示「局域网模式需要登录」

旧版将寓+账号登录失败和本地管理面板认证失败都返回 HTTP 401，网页误将所有 401 提示为「需要登录（局域网访问模式）」，因此看不到真正的登录失败信息。此版本修复：

- 寓+账号登录失败返回 HTTP 422，并显示服务端提供的错误原因（不显示账号密码、Token）；401 仅用于局域网面板 Basic Auth。
- 本机原生 App 添加账号不要求额外登录局域网面板。账号登录失败时保留表单内容供纠正、重试，账号不会假装添加成功。
- 如果寓+登录成功但 `config.json` 无法保存，明确提示保存权限问题。
- 新增模拟接口端到端测试，验证添加成功、失败、保存失败和局域网鉴权互不混淆。

**更新已编译 App**：用此工程覆盖 GitHub 仓库中的旧工程，然后运行 Actions > Build independent macOS app > Run workflow，下载与你 Mac 芯片对应的产物，替换旧版 `.app`。数据仍保存在 `~/Library/Application Support/yujia-signin/`，不会因替换 App 消失。不要删除数据目录或上传它到 GitHub。已运行的旧后台服务可能继续使用旧二进制，更新后**在 App 顶部点击「启动 / 修复」一次**，让 launchd 切换到新版本。

修复的是错误提示与账号保存失败时的诊断；真正的寓+登录失败可能仍需按新版报错检查账号、密码、区域或服务端限制。请勿把账号密码或 Token 发给别人。

## 用户在新 Mac 上的体验

1. 在 GitHub Actions 的对应构建中，下载 `YujiaSignIn-macOS-x86_64`（Intel）或 `YujiaSignIn-macOS-arm64`（Apple 芯片）构建产物，解压得到 `寓+签到-macOS-*.zip`。
2. 再次解压，只有一个 `寓+签到.app`；拖入 Mac 的「应用程序」，双击打开。**无需 Python、Xcode、命令行工具或旁边的源码文件夹**。
3. 打开后会自动检查 / 注册 `launchd` 的定时服务、启动本地面板。无需以管理员身份运行；关闭窗口后后台照常执行，每次重新登录系统可恢复。首次使用，在面板里直接添加账号和设置时间。
4. macOS 对未经苹果开发者账号公证的 App 可能阻止首次打开，可在 Finder 中右键 → 打开，或到系统设置 → 隐私与安全性按提示允许；这属于 Gatekeeper 限制，不是程序依赖。需要公证才能做到完全无安全提示。

## 从旧版迁移一次

从 App 顶部「寓+签到」菜单选择 **导入旧版账号和记录…**，选择旧的 `yujia-signin` 文件夹。会先停止用相同 `launchd` Label 安装的旧服务、在新目录备份旧数据后导入 `config.json` / `records.db`，保留原文件。**旧版本若曾用 `nohup python run_daily.py` 单独常驻运行，应在迁移前退出那个旧进程**，否则可能继续按 09:05 执行。

用户数据（属于正常 macOS 系统存储，对 Finder 日常使用透明）统一在：
`~/Library/Application Support/yujia-signin/`

包括 `config.json`、`records.db`、`signin.log`、`web.log`、`launchd.log`。关闭 App 或更新 App 不会删数据。复制 App 到新电脑后数据不会凭空同步；可在旧 Mac 使用导入迁移、备份方式迁移。

## 构建一次、以后所有新电脑直接复制

1. 新建私人 GitHub 仓库，将本工程**所有内容（包括 `.github/workflows/build-macos.yml`）**上传到根目录。仓库不要上传旧 `config.json`、token、数据库。
2. GitHub → Actions → `Build independent macOS app` → `Run workflow`。
3. 等两套构建完成后，在工作流详情的 **Artifacts** 下载对应架构安装包。每台新电脑只需得到那份已编译的 `.app`，不需要 GitHub、源码或编译工具。

构建流程会运行本地假 API 测试、打包 Python + 证书根、编译原生 Cocoa/WebKit 窗口、代码签名（ad-hoc），启动打包后的本地 Web 面板健康检查，再提供下载产物。流水线本身需要 macOS runner。现在提供的是**未经真正 macOS runner 实测的构建工程**，并不保证首次 CI 一定成功。

## macOS / Debian 分工

- macOS：从工作流下载完成的 `.app`；后台由系统 `launchd` 管理；图形界面负责账号、计划、日志、导入数据。
- Debian：保留仓库根目录的 `Dockerfile` 和 `docker-compose.yml`，Dockerfile 会从 `core/` 复制共用 Python 代码，`docker compose up -d --build` 即可部署（Docker 实机仍需你验证）。

## 注意

- macOS 12+，提供 Intel x86_64 和 Apple Silicon arm64 两个安装包。仅在可信设备和可信网络使用；默认只监听 127.0.0.1:8765。
- 端口 8765 不能同时被另一套旧版 Web 服务占用。若旧调度器是手工常驻启动，迁移前应停止旧进程。
- `launchd` 登录启动与 Mac 睡眠无关：电脑关机时不能签到；醒来/登录后会由调度器进行当日补跑。
- PyInstaller 捆绑的运行环境会使 `.app` 明显大于原有脚本。独立安装与不足 1MB 无法兼得。
