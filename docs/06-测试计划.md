# 阶段 0 交付物 6：测试与原版一致性验证计划

> 原则：以原版源码和可验证的原版行为为依据；能自动化的尽量自动化；对可运行的原版与 Rust 实现，优先构建"相同初始状态 + 相同操作序列 → 状态对照"测试。

## 2. 随机一致性三分类（硬性要求）

按 docs 总规范 §7 区分，不混为一谈：

1. **算法一致性**（必须逐位）：RandomXS128 与 JDK Random 的输出向量、counter 语义、快进（random(999) vs randomBoolean 补进）——L1 固定向量测试。
2. **统计性质**（抽验）：卡奖稀有度分布（万次抽样频率与理论概率偏差 < 2%）、宝箱箱型比例、药水 65/25/10 —— L4 抽样测试。
3. **具体随机序列一致性**（选择性）：同种子下地图结构、遭遇队列、首层卡奖等关键序列与原版一致——L8 对照，受限于能否运行原版；无法对照时以源码算法推演为依据并标注。

## 4. 原版对照策略（L8）

1. **静态对照（主渠道）**：原版源码行为 → 测试期望值。所有期望值注释标明原版文件:行号，禁止无出处断言。
2. **运行时对照（增强渠道）**：在可运行原版的环境采集（不阻塞移植）：
   - 地图：原版 debug 控制台 dump 地图节点/边（或读存档 path），转 JSON fixture；
   - 战斗：录制关键场景（如特定种子首层开局手牌、意图数值）人工对照；
   - 存档：用原版 XOR("key")+Base64 解码存档作为字段对照样本。
3. 采集脚本存放 `tools/parity/`（Java 侧小工具或存档解析器），不进入发行产物。

## 5. 自动化基建

- `scripts/test-all.ps1` / `.sh`：全 workspace test + clippy。
- 种子回归基线：`tests/fixtures/seed_baseline.json`（50 层关键事件序列），显式更新需 diff 审查。
- CI 不强制（本地开发）；提交前跑 L1-L5。

## 6. 不变量守护（debug_assert）

- HP/block/能量钳制边界；卡不在任何牌堆时不被动作引用；RNG counter 单调递增；Screen 返回栈不出现自环。
- 动作队列在 WAITING_ON_USER 时必空（允许 preTurn 例外——原版行为）。

## 7. 已知不可自动化项

- 终端渲染的视觉正确性（L7 人工+截图比对）。
- 原版运行时对照（依赖环境）。
- 手感类（键位舒适度）——人工验收。
