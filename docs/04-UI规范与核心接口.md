# 阶段 0 交付物 4：UI 设计规范与核心接口定义

> UI 与核心的协议（sts-interface）在实现任何屏幕之前先冻结。终端 UI 实现可与逻辑转译并行。

## 1. 协议总原则

1. UI 只提交玩家操作并展示核心计算结果；一切校验、结算、随机、状态变更由 sts-core 执行。
2. 协议必须能表达完整游戏所需的交互（docs/01 全清单），不因 UI 暂未实现而删减。
3. 核心给出的每个可选操作都带"是否可用 + 不可用原因（原版文案）"；UI 不做二次规则判断。
4. 协议双向皆可序列化（serde），便于录制回放测试（docs/06 §对照测试）。

## 2. 核心接口（sts-interface）

```rust
/// 玩家操作（战斗中/外统一枚举，覆盖 docs/01 全部交互）
pub enum PlayerCommand {
    // —— 战斗中 ——
    PlayCard { hand_index: usize, target: Option<MonsterRef>, x_energy: Option<u32> },
    CancelTargeting,
    EndTurn,
    OpenPileView(PileKind),          // Draw | Discard | Exhaust
    ClosePileView,
    InspectCard { card: CardRef },   // 单卡弹窗（含升级预览切换）
    ToggleUpgradePreview,
    UsePotion { slot: usize, target: Option<MonsterRef> },
    DiscardPotion { slot: usize },
    DiscardFromPotion { slot: usize }, // 丢弃（部分药水）
    ViewRelics { page: Option<usize> },
    // —— 选择屏 ——
    HandSelectToggle { index: usize },
    HandSelectConfirm,
    GridSelectToggle { index: usize },
    GridSelectConfirm,
    GridSelectCancel,
    // —— 地图 ——
    ChooseMapNode { x: i32, y: i32 },   // 含 Boss 虚拟节点 (-1,15)
    OpenMap, CloseMap,
    // —— 奖励 ——
    ClaimReward { index: usize },
    CardRewardPick { index: usize },
    CardRewardSkip,
    SingingBowl,
    BossRelicPick { index: usize },
    BossRelicSkip,
    // —— 房间 ——
    CampfireChoose(CampfireOption),     // Rest|Smith|Dig|Lift|Recall|Toke
    ShopBuy { item: ShopItemKind, index: usize },
    ShopPurge { deck_index: usize },
    LeaveShop,
    EventChoose { index: usize },       // 含 Neow（由 view 提供选项集）
    // —— 查看 ——
    ViewDeck { sort: Option<DeckSort> },
    CloseOverlay,
    // —— 外壳 ——
    MainMenuAction(MainMenuAction),     // NewRun|Continue|Custom|Daily|Compendium|Stats|Settings|Quit
    CharSelect { class: CharacterClass, ascension: u8, seed: Option<String> },
    ToggleSetting { key: SettingKey },
    AbandonRun,
    ReturnToMenu,
    Help,                                // 关键词/帮助页
}

pub struct CommandResult {
    pub accepted: bool,
    pub rejection_reason: Option<LocalText>,   // 原版 cantUseMessage 等价
    pub events: Vec<LogEvent>,                 // 结算日志（伤害/格挡/触发…供战斗日志）
    pub screen_changed: bool,
}

/// 渲染视图：核心按当前 Screen 一次性给出全部所需信息
pub struct GameView {
    pub screen: ScreenKind,           // 23 屏等价枚举
    pub top_bar: TopBarView,          // HP/格挡/能量/金币/层号/遗物摘要/药水栏
    pub battle: Option<BattleView>,   // 敌我、意图、手牌、牌堆计数、结束回合可用性
    pub map: Option<MapView>,         // 节点图 + 可达标记 + 当前位置 + 图例
    pub selection: Option<SelectionView>, // 卡奖/网格/手选/商店/事件/Neow 的选项列表
    pub overlays: Vec<OverlayView>,   // 牌堆浏览/遗物详情/帮助
    pub log: Vec<LogEvent>,           // 战斗日志环形缓冲
}
```

规则细节：
- `BattleView.hand[i]` 含：名称、类型、费用（含 X/不可打出）、动态数值（!D!/!B!/!M! 求值结果与 modified 标志）、关键词列表、可打出性与原因、目标需求（无目标/需选目标/全体）。
- `BattleView.enemies[i]` 含：名称、HP/maxHP、格挡、意图（图标语义枚举 + 伤害预览 ×N）、能力列表（名称+描述+层数）。
- `MapView` 采用核心提供的节点与边集合，可达节点显式标记（含 Wing Boots 同排连通、Boss 可达）——**可达判定只在核心**。
- 所有文本走 `LocalText`（key + 参数），终端负责排版；`[E]/#r` 等标记由核心预解析为 span（见 §6）。

## 3. 终端 UI 设计规范（sts-terminal）

### 3.1 总体布局（≥100×30 可玩，自适应 80×24 降级；无鼠标依赖，纯键盘）

```
┌─────────────────────────────── 顶栏（固定 1-2 行）──────────────────────────────┐
│ 铁甲战士  HP 72/80 ▏格挡 5 ▏能量 ●●●○ 2/3 ▏金 99 ▏层 12 ▏遗物:8 ▏药水:2        │
├──────────────────────────────── 主区（自适应）───────────────────────────────┤
│  战斗：敌人区（上）  →  战斗日志（右/下角小窗，可折叠）                          │
│        手牌区（下，编号 1..n，横排卡片摘要）                                     │
│  地图：节点图（左）+ 图例 + 当前选中信息（右）                                   │
│  选择屏：标题 + 正文 + 编号选项列表                                              │
├─────────────────────────────── 状态/提示行（固定 1-2 行）──────────────────────┤
│ [1-9]出牌 [E]结束回合 [D]牌堆 [R]遗物 [M]地图 [H]帮助   ←（当前提示）           │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 3.2 地图表达（硬性要求）

- 15 行 × 7 列自底向上渲染（0 层在下，Boss 在顶行上方居中，与原版视觉方向一致）。
- 每节点一个字符：`M`战斗 `E`精英 `$`商店 `T`宝箱 `R`篝火 `?`事件 `B`Boss；已走过路线用 `═║╚╗` 等连线字符或 `.` 描边；当前位置 `@`；本回合可达节点用高亮色/反显并附序号（选择时直接输入序号）。
- 分叉/汇聚必须能看出边：节点间用列内连线绘制；终端宽度不足时优先保正确性（允许省略装饰字符）。
- 节点附带已完成标记（已访问 `*`）；绿钥匙精英显示火焰色标。

### 3.3 战斗面板（硬性要求）

- 敌人一行一个：`[1] 颚虫  45/45 ▏格挡 5 ▏意图: 攻击 12 ×2 ▏[力量 3][虚弱 2]`；意图用图标字符 + 数字（原版 Intent 17 值映射到固定符号表）。
- 手牌横排摘要卡（名称/费用/简述 1 行）；选中/悬停卡展开 3-5 行详情 + 关键词 tip（对应原版 renderCardTip）。
- 需要选目标时进入目标模式：敌人列表反显可选中，`Esc/右键等价键` 取消（对应原版两段式出牌）。
- 伤害预览：卡详情内显示当前 `!D!` 求值（核心已按 calculateCardDamage 算好）。
- 战斗日志：每逻辑步的 LogEvent（伤害/格挡/施加上下文），固定缓冲 200 条，可翻页。
- 牌堆计数：抽/弃/耗数量常显；打开牌堆浏览为只读排序列表（原版 Frozen Eye 排序差异由核心实现）。

### 3.4 交互模型（纯键盘）

- 数字键：选择/出牌（对应原版 1-0 热键）；方向键 + Enter：列表导航；`Esc`：取消/返回/设置（等价原版 Esc 路由表，具体路由在核心 flow）；`E`：结束回合；`H`：帮助。
- 任何屏幕底部提示行显示当前可用键位；不可用操作不显示或灰显并给原因。
- X 费卡：打出时若 `x_energy` 未指定，默认用当前全部能量（对应原版钳制语义）；UI 提供 `1-9` 选择投入能量的交互。
- 输入不回显、光标隐藏；单缓冲重绘（整帧构建后一次输出），避免闪烁。

### 3.5 文本与编码

- 全程 UTF-8；Windows 下启用 VT 序列（crossterm 自动处理）；检测终端不支持颜色时降级为无色（保留符号语义）。
- 文本宽度用 unicode-width 计算换行；中文按字符断行（对应原版 lineBreakViaCharacter 分支），英文按词断行（NL/TAB 协议）。
- 颜色编码固定表：伤害红 `#r`、能量黄、格挡绿、稀有度（普通灰/罕见蓝/稀有金/诅咒紫）、可达地图高亮白。**不在颜色中携带规则信息**（信息必须有非颜色冗余：符号或文字）。

### 3.6 屏幕清单与返回栈

- 核心已管理 Screen 状态机（23 屏 + 返回栈 + DEATH 接管），终端按 `GameView.screen` 渲染对应面板并转发键位 → PlayerCommand。终端不维护自己的屏幕栈。
- 弹窗类（单卡查看/遗物详情/帮助/设置）作为 OverlayView 栈渲染，关闭即弹栈。

### 3.7 刷新与兼容

- 每次收到新 GameView 全量重绘（终端实现简单、可靠优先）；不逐帧动画。
- 终端过窄（<80 列）时：地图可横向滚动（方向键），战斗面板纵向堆叠；关键信息（HP/能量/选项）永不被截断——超宽文本自动换行而非截断。
- Ctrl+C 恢复终端状态后退出；异常退出时 raw mode 逃逸由 Drop 保证。

### 3.8 开发期示例状态

- sts-tests 提供 `fixture_game()` 构造指定状态（手牌/敌人/地图），供 UI 联调；**示例状态只进测试与 `--demo-view` 调试入口，不进正常游戏路径**。

## 4. 核心与 UI 的责任边界（冻结）

| 事项 | 归属 |
|---|---|
| canUse/能量/目标合法性 | 核心 |
| 药水槽校验、商店扣钱、奖励领取 | 核心 |
| 可达节点判定（含 Wing Boots） | 核心 |
| 排序（图鉴/牌堆浏览顺序、Frozen Eye 差异） | 核心 |
| 键位映射、焦点管理、滚动、翻页 | 终端 |
| 颜色/符号渲染、换行排版 | 终端（按核心 span 指示） |
| 战斗日志缓冲上限与显示 | 终端显示 / 核心生成 |
| 随机（一切） | 核心 |

## 5. 协议演进规则

- 新增交互 → 先扩 PlayerCommand/GameView（保持向后兼容的字段新增），核心实现后再接 UI。
- 禁止终端"猜测"未实现的规则（如本地预计算伤害）。
