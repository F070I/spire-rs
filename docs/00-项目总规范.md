# Rust 文字版《杀戮尖塔》项目总规范

版本：v1.0（阶段 0 冻结版）
日期：2026-10-16
移植依据：`C:\Users\17366\OneDrive\Desktop\MySlayTheSpire-master`（反编译源码，desktop-1.0 完整版，含 4 角色与 Act 4）

## 一、项目目标

从原版《杀戮尖塔》源码重新实施一个 Rust 版本，保留完整游戏规则与内容，将原版图形界面替换为纯文字终端 UI。这是以原版源码为依据的**语义移植**，不是玩法类似的新游戏。

最终要求：
- 使用 Rust 实现。
- 游戏机制尽可能忠实于原版，包括所有相关规则、触发顺序、边界情况和完整游戏流程。
- UI 与游戏逻辑严格分离，未来更换 UI 不需要重写游戏规则。
- 稳定、清晰、易操作的文字终端界面。
- 不保留原版不需要的美术、动画和音效资源。
- 最终独立运行程序体积小于 20 MB（按各平台实际发行构建产物测量）。
- 跨平台：Windows x86_64（`sts.exe` 独立运行）、macOS Intel x86_64（原生可执行）、macOS Apple Silicon ARM64（架构兼容，保留构建能力）。
- 不以最小可玩版本、演示版本或部分机制实现作为最终交付目标。

## 二、工作原则

1. 先建立完整架构和移植计划，再开始正式实现（本文档即该计划）。
2. 从项目一开始就确定完整功能范围，不允许以先实现部分功能为理由跳过已纳入目标的机制。
3. 按模块逐步完成转译，但每个模块都必须遵循已冻结的整体架构（docs/03）。
4. 禁止没有依据地简化原版规则，禁止凭记忆重新设计游戏机制。一切以 docs/source-inventory/ 的实读记录为依据。
5. 原版源码是主要实现依据。源码中存在的特殊逻辑、调用顺序和隐含约束，应保留其语义——**包括已确认的反编译伪影与疑似原版 bug**（见 docs/07 风险清单中的"保真"条目）。
6. 不得为了适应 UI 而修改游戏规则。
7. 不得为了方便实现而硬编码原版本应动态生成的地图、随机结果或奖励。
8. 不要每次新增功能都重写整体架构。需要改变架构时，先说明必要性、影响范围、替代方案和迁移成本。
9. 对尚未理解或尚未验证的机制，在模块记录中明确标记为未完成，不得声称已忠实移植。
10. 所有关键机制都必须有对应的验证方式（docs/06）。

## 四、关键事实速查（来自源码实读）

- 原版引擎：libgdx + Spine 骨骼动画 + Steamworks/Twitch/Discord 集成，共 2257 个 Java 文件，其中游戏本体约 1900 类（com.megacrit.cardcrawl 下），其余为第三方依赖（不移植）。
- 卡牌 447 类（红 75 / 绿 75 / 蓝 76 / 紫 77 / 无色 39 / 诅咒 14 / 状态 5 / 临时 9 / 选项 5 / 废弃 63）；遗物 177 注册；药水 35/职业；怪物 73 类；事件三幕 31 + 神龛 6 + 一次性 14。
- 随机数：libgdx RandomXS128（xorshift128+）包装类 `random/Random.java`（带 counter），12 条流同 seed 异 counter，5 条每层重播种；部分洗牌用 JDK LCG（java.util.Random）。
- 核心调度：GameActionManager 四队列（actions / preTurnActions / cardQueue / monsterQueue），每逻辑帧一个 currentAction。
- 全局状态：原版几乎全部为 static（AbstractDungeon ~150 个静态字段）→ 本项目收敛为单一状态树。

## 五、工程约定

- 语言：Rust（stable，当前 1.99.0）。
- Rust edition 2021；不使用 nightly 特性。
- 模块命名：sts-data / sts-core / sts-interface / sts-terminal / sts-tests（见 docs/03）。
- 随机数、调用顺序、浮点取整等"可复现性敏感点"在实现时逐条对照 docs/source-inventory/ 的对应记录，不得即兴发挥。
- 每个模块完成后在 docs/modules/<模块>.md 记录：实现位置、验证依据（原版文件+行为）、测试结果、已知差异。
- 文档与代码同仓库演进；规范变更需先改文档（附变更说明）再改代码。

## 六、范围裁决规则（实现中遇到分歧时按此裁决）

1. 原版源码行为 > 社区 wiki 描述 > 直觉。
2. 反编译瑕疵：若确认是原版正式版行为（逻辑可达且无守卫），**保真复刻**并记录；若确认是反编译伪影（死代码、不可达分支），不移植并记录理由。
3. 原版不可回放的随机调用（MathUtils.random、无种子 java.util.Random）仅在纯表现场景；若出现在影响游戏状态的路径，改为接种子 RNG 并记录差异（见 docs/07 决策 D-03）。
4. 原版为图形 UI 设计的等待时间（WaitAction 时长、动画帧）不保留时长，但**保留其作为队列屏障的语义**（顺序不变，等待即时完成）。
