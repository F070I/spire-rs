# 盘点原始记录 02：卡牌系统（cards/，447 文件）

> 路径均相对 `src/main/java/com/megacrit/cardcrawl/`。阶段 0 原始盘点记录。

## 0. 枚举与 ID 定义位置

- **没有独立的 AbstractCardEnum/CardEnum 文件**。卡牌 ID 是纯字符串 `cardID`（构造时传入），如 `"Strike_R"`、`"Perfected Strike"`；每张卡类有 `public static final String ID`。
- 全部枚举都是 `AbstractCard` 内部枚举（`cards/AbstractCard.java` L280-323）：
  - `CardColor`: RED, GREEN, BLUE, PURPLE, COLORLESS, CURSE
  - `CardRarity`: BASIC, SPECIAL, COMMON, UNCOMMON, RARE, CURSE
  - `CardTags`: HEALING, STRIKE, EMPTY, STARTER_DEFEND, STARTER_STRIKE
  - `CardTarget`: ENEMY, ALL_ENEMY, SELF, NONE, SELF_AND_ENEMY, ALL
  - `CardType`: ATTACK, SKILL, POWER, STATUS, CURSE
- `DamageType` 在 `cards/DamageInfo.java` L201：`NORMAL, THORNS, HP_LOSS`。

文件规模：根目录核心类 9 个（AbstractCard 2886 行、CardGroup 1321 行、Soul 407 行、DamageInfo 209 行、CardQueueItem、CardSave、DescriptionLine、SoulGroup、CardModUNUSED[未使用]）；卡包子包：blue 76、purple 77、red 75、green 75、colorless 39、deprecated 63（废弃）、curses 14、tempCards 9、status 5、optionCards 5。

## 1. AbstractCard 字段清单

### 数值核心（构造器 L430-444 初始化为 -1 哨兵）
| 字段 | 语义 |
|---|---|
| `baseDamage / baseBlock / baseMagicNumber / baseHeal / baseDraw / baseDiscard` | 卡面基础值，升级只改 base*；-1 表示不用此数值 |
| `damage / block / magicNumber / heal / draw / discard` | 结算用当前值 = base* 经修正后的结果，由 `applyPowers()` / `calculateCardDamage()` 重算 |
| `isDamageModified / isBlockModified / isMagicNumberModified` | 当前值≠基础值（UI 绿/红着色） |
| `isMultiDamage` + `int[] multiDamage` | 全体目标卡每个敌人一个伤害值 |
| `damageType` / `damageTypeForTurn` | 出厂伤害类型 / 战斗中可临时改（resetAttributes 还原） |

### 身份与元数据
| 字段 | 语义 |
|---|---|
| `cardID` | 唯一字符串 ID |
| `name` / `originalName` | 显示名（升级后尾部加 "+"） |
| `rawDescription` | 原始描述（含 `NL` 换行、`[E]`、`!D!`/`!B!`/`!M!` 动态变量、`*关键词`） |
| `description: ArrayList<DescriptionLine>` | 排版后的行缓存 |
| `keywords` | 从描述解析出的关键词 |

| `price` | 商店售价（COMMON 50 / UNCOMMON 75 / RARE 150） |

## 2. use() 签名与结算方式

```java
public abstract void upgrade();
public abstract void use(AbstractPlayer abstractPlayer, AbstractMonster abstractMonster);
public abstract AbstractCard makeCopy();
```

- **伤害/格挡绝不直接结算**：`use()` 内一律 `addToBot/addToTop(new XxxAction(...))` 投递到动作队列。
- 调用链：玩家操作 → `GameActionManager.cardQueue`（CardQueueItem）→ `AbstractDungeon.player.useCard(card, monster, energyOnUse)`（`characters/AbstractPlayer.java:1472`）：
  1. 攻击卡动画；
  2. **`c.calculateCardDamage(monster)`**（打出瞬间重算）；
  3. X 费钳制：`cost == -1 && totalCount < energyOnUse` 时 `c.energyOnUse = EnergyPanel.totalCount`；
  4. `c.use(this, monster)`；
  5. `addToBottom(new UseCardAction(c, monster))`；
  6. `hand.triggerOnOtherCardPlayed(c)`、`hand.removeCard(c)`、`cardInUse = c`；
  7. 扣费：`energy.use(c.costForTurn)`（Corruption 且是技能免；freeToPlay/autoplay 免）。
- **isInnate 的处理位置**：`CardGroup.initializeDeck(CardGroup)` L1029-1063——洗牌后把 `isInnate` 或瓶装标记的卡全部 `addToTop` 置顶；超出手牌上限时补发 DrawCardAction（进 preTurnActions）。

## 3. 升级机制

- 每张卡重写 `upgrade()`，习惯 `if (!this.upgraded) { upgradeName(); upgradeXxx(n); }` 防重入。
- 基类工具（L861-900）：
  - `upgradeName()`：`timesUpgraded++; upgraded = true; name += "+";`；
  - `upgradeDamage(n)/upgradeBlock(n)`：`baseXxx += n; upgradedXxx = true;`（只改 base）；
  - `upgradeMagicNumber(n)`：`baseMagicNumber += n; magicNumber = baseMagicNumber;`（直接同步）；
  - `upgradeBaseCost(newCost)`：`cost = newCost`，保持 `costForTurn - cost` 差值，钳负。用例：Corruption 3→2、Omniscience 4→3、Eruption 2→1、Zap 1→0、Nightmare 3→2 等。
- `canUpgrade()`（L836-841）：CURSE/STATUS 或已升级 → false。例外：`SearingBlow.canUpgrade()` 恒 true，`upgrade()` 不调 upgradeName 而是 `upgradeDamage(4 + timesUpgraded); timesUpgraded++; name = NAME + "+" + timesUpgraded`，构造器 `SearingBlow(int upgrades)` 接受已有次数，`makeCopy()` 传递。
- 升级改文本：`this.rawDescription = cardStrings.UPGRADE_DESCRIPTION; initializeDescription();`。其他花样：Blasphemy `selfRetain=true`；Rainbow/Discovery `exhaust=false`；EchoForm `isEthereal=false`；InfiniteBlades `isInnate=true`。
- 升级分支行为：`use()` 里读 `this.upgraded`（Catalyst、Fission、MultiCast 等）。

## 4. 费用机制

- 三种修改 API（L2168-2223）：
  - `updateCost(amt)`：对 `cost` 相对增减并同步 costForTurn 差值（诅咒/状态禁止，除 Pride/Slimed）。
  - `setCostForTurn(amt)`：仅设 `costForTurn`；**只在 `costForTurn >= 0` 时生效**——负费卡（-1 X 费、-2）免疫（Bullet Time 用此）。
  - `modifyCostForCombat(amt)`：增减 `costForTurn` 并把结果写回 `cost`（Entangled 等）；`costForTurn <= 0` 时改为改 `cost`。
- 费用重置：`resetAttributes()`（L2225）把 `costForTurn = cost; isCostModifiedForTurn = false` 连同 damage/block/magicNumber/damageTypeForTurn 重置。调用点：`AbstractRoom.endTurn()` L422-439 对 drawPile/discardPile/hand/hoveredCard 全量重置。
- **X 费卡**：`CardQueueItem.energyOnUse` 携带当时能量；`useCard` 钳制不超当前能量；卡内 `use()` 把 `energyOnUse` 传给专属 Action 自行循环 N 次。`ignoreEnergyOnUse` 无视钳制。
- `cost = -2`：不可打出占位。
- `freeToPlay()`（L2247）：`freeToPlayOnce` 或玩家有 FreeAttackPower 且卡是攻击。

## 5. canUse / canPlay 逻辑

`canUse(AbstractPlayer p, AbstractMonster m)`（L1167-1175）三重判定：
1. STATUS 且 `costForTurn < -1` 且无 Medical Kit → 不可用；
2. CURSE 且 `costForTurn < -1` 且无 Blue Candle → 不可用；
3. `cardPlayable(m) && hasEnoughEnergy()`。

- `cardPlayable(m)`（L1093）：ENEMY/SELF_AND_ENEMY 目标必须有活的指定怪物。
- `hasEnoughEnergy()`（L1101-1144）依次：`turnHasEnded` → 玩家每个 Power 的 `canPlayCard(this)` → EntanglePower 且卡是 ATTACK → 遗物 `canPlay`/blight `canPlay`/**手牌每张卡的 `canPlay(card)`** → 最后能量 `EnergyPanel.totalCount >= costForTurn || freeToPlay() || isInAutoplay`。
- 手牌层 `CardGroup.canUseAnyCard()`（L97-105）用于结束回合按钮。

## 6. CardTags 枚举

`HEALING, STRIKE, EMPTY, STARTER_DEFEND, STARTER_STRIKE`（仅 5 个成员）。STRIKE 供 PerfectedStrike 计数、Feed/Reaper/Bite 的 HEALING 标记；STARTER_* 供初始卡识别（要求 rarity==BASIC）；EMPTY 观者"空"系列。

## 7. 伤害/格挡数值链

**两个核心入口**（都在 AbstractCard）：
- `applyPowers()` L2428-2509（手牌静态重算，无目标）：先 `applyPowersToBlock()`（baseBlock → 玩家 powers `modifyBlock` → `modifyBlockLast` → floor → block）；伤害侧 baseDamage → 每个遗物 `atDamageModify` → 玩家 powers `atDamageGive` → 玩家姿态 `stance.atDamageGive` → 玩家 power `atDamageFinalGive` → floor、负值钳 0 → damage。多目标时对每怪独立算 multiDamage[]（不含目标侧 power）。
- `calculateCardDamage(AbstractMonster mo)` L2537-2646（带目标）：额外插入目标侧 `mo.powers` 的 `atDamageReceive` 与 `atDamageFinalReceive`（跳过 isDying/isEscaping），写入 damage 或 multiDamage[]。

**调用层**：`CardGroup.applyPowers()` 遍历手牌；调用点：`AbstractPlayer.onCardDrawOrDiscard()`、GameActionManager L445、UseCardAction、SeekAction/DiscardAction 等。打出瞬间 `useCard` 调 `calculateCardDamage(monster)`。

**结算层**：`use()` 里的 `new DamageInfo(p, this.damage, this.damageTypeForTurn)` 只带显示值；真正扣血在 `DamageAction/DamageAllEnemiesAction` → 目标 `damage(info)`。非卡牌来源用 `DamageInfo.applyPowers(owner, target)`（DamageInfo.java L31-138）。

**单卡多段伤害**：多次 `addToBot(new DamageAction(...))` 循环；多目标用 `isMultiDamage + multiDamage[] + DamageAllEnemiesAction`；动态基数卡重写 `applyPowers/calculateCardDamage`（PerfectedStrike：baseDamage += magicNumber × 全牌组 STRIKE 数；SpiritShield：baseBlock = 手牌数 × magicNumber；Blizzard 动态改 rawDescription）。

## 10. 生命周期方法

- `makeCopy()`：全新实例。特例 SearingBlow 拷贝携带 timesUpgraded。
- `makeStatEquivalentCopy()`（L1064-1088）：makeCopy 后逐次 `upgrade()` timesUpgraded 次，再手工复制 name/target/upgraded/base*/cost/costForTurn/misc/瓶装标记等（Nightmare 复制用）。
- `makeSameInstanceOf()`：makeStatEquivalentCopy + 保留 uuid。
- `initializeTitle()`（L549）/ `initializeDescription()`（L563）：按名字宽度选字体、把 rawDescription 分词排版为 DescriptionLine；解析 `NL`、`[E]`、`!D!`/`!B!`/`!M!`、`*keyword` 金色高亮并填 keywords。任何改 rawDescription/数值的卡都要手动重调。
- `displayUpgrades()`（L843）：升级预览时把当前值抬到 base 值（`makeCopy().upgrade().displayUpgrades()`——升级函数被当纯函数用）。
- `resetAttributes()`：回合末还原。
- 其他钩子：`triggerWhenCopied`、`switchedStance`、`tookDamage`、`onRemoveFromMasterDeck`、`getMetricID()`（cardID+["+timesUpgraded"]）。

## 11. Rust 移植风险点

1. **继承多态规模**：447 文件全部是 AbstractCard 子类，3 抽象方法 + 约 40 可覆写钩子 → trait + enum 分发。
2. **UI/逻辑强耦合**：2886 行中渲染占约 60% → 拆除渲染字段；keywords 解析与 `[E]`/`!D!` 语法保留为纯数据。
3. **渲染路径副作用**：`renderUpgradePreview` 直接 `makeCopy().upgrade()`——Rust 里"预览升级"应做纯查询。
4. **动态文本/状态回写**：Blizzard/SpiritShield 在 applyPowers 中改描述——渲染期从 (baseDamage/damage, magicNumber, 场景) 派生文本。
5. **全局单例访问**：卡逻辑引用 AbstractDungeon.actionManager/player/languagePack 静态全局 → context 参数。
6. **动作 this 引用 + uuid 反查**：Rust 用 `CardId + instance uuid` 的 slotmap。
7. **数值哨兵 -1/-2 双义**：base*=-1 无此数值、cost=-1 X 费、-2 不可打出 → Rust 建模为专用枚举/Option。
8. **canUpgrade 默认单次 + SearingBlow 例外**、CardSave 序列化（name+upgraded+timesUpgraded+misc）。
9. **反编译瑕疵**：`createCardImage()` L1013-1019 BLUE 分支缺 break 落入 PURPLE（配色 bug）；`getCardBg()` 死代码；`useBlueCandle/useMedicalKit` @Deprecated（逻辑已内联 canUse）。
10. **触发顺序语义**：UseCardAction 构造器（onUseCard/triggerOnCardPlayed）→ use() 的动作入队 → UseCardAction.update()（onAfterUseCard、去向、重置）→ 扣能在 useCard 而非动作内；连锁（Nightmare 复制、Echo Form 翻倍、双持）必须同样时序。
