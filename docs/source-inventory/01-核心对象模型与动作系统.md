## 1. AbstractCreature：字段与职责

文件：`core/AbstractCreature.java`（1055 行，抽象基类，子类 `AbstractPlayer`、`AbstractMonster`）

### 核心状态字段（49–147 行）
| 字段 | 语义 |
|---|---|
| `name`, `id`, `isPlayer` | 标识 |
| `currentHealth`, `maxHealth`, `currentBlock` | 生命/格挡三件套（int，public 直接可改） |
| `powers = new ArrayList<AbstractPower>()` (110) | power 列表，游戏内多处直接遍历/排序 |
| `gold`, `displayGold` | 金币（怪物也有 gold，供偷金逻辑用） |

| `lastDamageTaken` (120) | 本场战斗最后一次受击量，`AbstractPlayer.damage` 里 `lastDamageTaken = min(damageAmount2, currentHealth)` |

| `hb`, `healthHb`, `drawX/drawY`, `animX/animY` 等 | 渲染层（不移植） |

### 关键逻辑
- **`damage(DamageInfo)` 是抽象方法**（160 行），具体扣血管线在子类：`AbstractPlayer.damage`（`characters/AbstractPlayer.java:1508` 起）完整链条为：减格挡 → 攻击方 relic/power `onAttackToChangeDamage` → 受击方 relic/power `onAttackedToChangeDamage` → `onAttack` → `onAttacked` → `onLoseHpLast` → `lastDamageTaken` 记录 → `currentHealth -= ...`（后续还有 isBloodied、死亡判定）。
- **`decrementBlock(info, damageAmount)`（186–214）**：`HP_LOSS` 类型完全无视格挡；否则三分支：伤害 > 格挡 → 扣格挡后剩余穿透（`loseBlock()` 全清 + `brokeBlock()`）；等于 → 全格挡归零（`loseBlock()` + `brokeBlock()`，"Absorbed"文案）；小于 → `loseBlock(damageAmount)` 部分消耗。`brokeBlock()`（173）在怪物破格挡时触发**玩家**身上所有 relic 的 `onBlockBroken`。
- **`maxHealth` 语义**：`increaseMaxHp(amount)`（216）会同时 `heal(amount, true)`；`decreaseMaxHealth`（228）把 maxHealth 钳到最少 1。
- **`heal(amount, showEffect)`（402–442）**：Endless+Muzzle 减半；**`isDying` 直接不治疗**；依次过 `AbstractDungeon.player.relics` 的 `onPlayerHeal`（仅 isPlayer 时）→ 自身每个 power 的 `onHeal` → 加血夹到 maxHealth → 半血以上解除 isBloodied 并触发 relic `onNotBloodied`。
- **`addBlock(int)`（448–495）**：玩家时先过 relic `onPlayerGainedBlock(float)` → power `onGainedBlock` → 再过**所有怪物的 power** 的 `onPlayerGainedBlock` → `currentBlock += floor(tmp)` → 上限 999。
- **`loseBlock` 重载家族（497–528）**：`loseBlock()` = 清空全部格挡；`loseBlock(int amount)` 扣指定量、下限 0。
- **`addPower`（539）**：同 ID 则 `stackPower(amount)` + `updateDescription()`，否则加入列表；**不排序**（ApplyPowerAction 新增时才 `Collections.sort(powers)`）。
- **回合钩子**：`applyStartOfTurnPowers`（567，每个 power `atStartOfTurn`）、`applyTurnPowers`（575，`duringTurn`）、`applyStartOfTurnPostDrawPowers`（583）、`applyEndOfTurnTriggers`（591，非玩家先 `atEndOfTurnPreEndTurnCards(false)`，然后所有人 `atEndOfTurn(isPlayer)`）。

## 2. AbstractGameAction 完整结构

文件：`actions/AbstractGameAction.java`（100 行）

- 字段：`duration`（剩余时间）、`startDuration`（初始时间，"首帧"判据）、`actionType`、`damageType`、`isDone`、`amount`、`attackEffect`、`target`、`source`。
- **`ActionType` 枚举（18 值）**：`BLOCK, POWER, CARD_MANIPULATION, DAMAGE, DEBUFF, DISCARD, DRAW, EXHAUST, HEAL, ENERGY, TEXT, USE, CLEAR_CARD_QUEUE, DIALOG, SPECIAL, WAIT, SHUFFLE, REDUCE_POWER`。
- **`AttackEffect` 枚举（纯视觉）**：`BLUNT_LIGHT, BLUNT_HEAVY, SLASH_DIAGONAL, SMASH, SLASH_HEAVY, SLASH_HORIZONTAL, SLASH_VERTICAL, NONE, FIRE, POISON, SHIELD, LIGHTNING`。
- `update()` 抽象；`tickDuration()`：`duration -= deltaTime; if (duration < 0) isDone = true;`。惯例双段结构：`duration == startDuration` 首帧做实际效果，末尾 tickDuration。
- `setValues` 三个重载（32–51）：填 target/source/amount 并重置 duration=0.5F；DamageInfo 版 `source = info.owner; amount = info.output`。
- `shouldCancelAction()`（91）：target 为 null、source 已死、target `isDeadOrEscaped()` → 取消（THORNS 例外放行）。
- **入队语义**（`actions/GameActionManager.java`）：
  - `addToBottom(action)`（103）：`actions.add(action)` 队尾；**仅当 `room.phase == COMBAT` 才收，非战斗房静默丢弃**。
  - `addToTop(action)`（160）：插队头（LIFO）。
  - `addToTurnStart(action)`（166）：进 `preTurnActions` 队头。
  - `addToNextCombat(action)`（83）：进 `nextCombatActions` 暂存，下次战斗开始 `useNextCombatActions()`（90）批量转正。
  - 语义差别：**top = 立即插队；bottom = 排队；nextCombat = 跨房间延迟**。

## 3. GameActionManager 完整回合循环

文件：`actions/GameActionManager.java`（634 行）

### 状态字段（54–72）
- 三条动作队列 `actions`、`preTurnActions`、`nextCombatActions`；
- `cardQueue: ArrayList<CardQueueItem>`（card、monster、energyOnUse、ignoreEnergyTotal、autoplayCard、randomTarget、isEndTurnAutoPlay）；
- `monsterQueue: ArrayList<MonsterQueueItem>`；
- 统计：`cardsPlayedThisTurn/ThisCombat`、`orbsChanneledThisTurn/ThisCombat`、`uniqueStancesThisCombat`、`mantraGained`，静态 `totalDiscardedThisTurn / damageReceivedThisTurn / damageReceivedThisCombat / hpLossThisCombat / playerHpLastTurn / energyGainedThisCombat / turn`；
- `phase`：**Phase 枚举只有 2 值：`WAITING_ON_USER, EXECUTING_ACTIONS`**（回合推进不是状态机，而是 getNextAction 的 if-else 优先级分支）；
- `hasControl`、`turnHasEnded`、`usingCard`、`monsterAttacksQueued = true`、`currentAction / previousAction / turnStartCurrentAction / lastCard`。

### `update()`（175–200）
```
WAITING_ON_USER    → getNextAction(); return;
EXECUTING_ACTIONS  → if (currentAction != null && !currentAction.isDone) currentAction.update();
                     else { previousAction = currentAction; currentAction = null; getNextAction();
                            if (currentAction == null && room.phase == COMBAT && !usingCard) {
                                phase = WAITING_ON_USER; hand.refreshHandLayout(); hasControl = false; }
                            usingCard = false; }
```
要点：**每帧最多推进一个 currentAction**；动作结算完同帧立即取下一个；只有全部队列空且非消费卡牌时才回到 WAITING_ON_USER。

### `getNextAction()` 分支顺序（212–477，按代码实际顺序）
1. **`!actions.isEmpty()`** → `currentAction = actions.remove(0)`；`phase = EXECUTING_ACTIONS; hasControl = true`。
2. **否则 `!preTurnActions.isEmpty()`** → 从 `preTurnActions` 弹出。
3. **否则 `!cardQueue.isEmpty()`** → `usingCard = true`，消费 `cardQueue.get(0)`（处理完 `cardQueue.remove(0)`，一帧一条）：
   - `card == null`（回合末自动打出占位）→ **`callEndOfTurnActions()`**（479–491）：`room.applyEndOfTurnRelics()`（relic/blight `onPlayerEndTurn`）→ `room.applyEndOfTurnPreCardPowers()`（玩家 power `atEndOfTurnPreEndTurnCards(true)`）→ `addToBottom(TriggerEndOfTurnOrbsAction)` → 手牌每张 `triggerOnEndOfTurnForPlayingCard()` → `stance.onEndOfTurn()`。
   - `c.equals(lastCard)` → 只清 lastCard。
   - 队列仅剩 1 条且 `isEndTurnAutoPlay` → 禁用 "Unceasing Top" 直到回合结束。
   - `c.isInAutoplay = item.autoplayCard`；`item.randomTarget` → 用 **`AbstractDungeon.cardRandomRng`** 随机目标。
   - **canUse 判定**：`c.canUse(player, monster) || c.dontTriggerOnUseCard` → 可打：
     - `freeToPlay()` → `freeToPlayOnce = true`；填 `energyOnUse`/`ignoreEnergyOnUse`；
     - onPlayCard 钩子链（受 `!card.dontTriggerOnUseCard` 保护，L274-307）确切顺序：**玩家 powers → 每只怪的 powers → 玩家 relics → stance.onPlayCard → blights → 手牌每张 onPlayCard → 弃牌堆每张 → 抽牌堆每张**；
     - `player.cardsPlayedThisTurn++`，加入 `cardsPlayedThisTurn/ThisCombat`；25 张解锁 INFINITY、≥20 置 combo、10 张 Shiv 解锁 NINJA；
     - 目标是 ENEMY 但怪物已死/null → 卡从 limbo 淡出，**不调用 useCard**；
     - 否则 **`AbstractDungeon.player.useCard(card, monster, energyOnUse)`**。
   - 不可打 → limbo 内淡出 + ThoughtBubble 显示 `cantUseMessage`；autoplay 卡则强制 `dontTriggerOnUseCard=true` + `addToBottom(new UseCardAction(c))`。
4. **否则 `!monsterAttacksQueued`** → 置回 true，`if (!room.skipMonsterTurn) monsters.queueMonsters()`（按 monsters 列表顺序把活着的或 halfDead 的怪塞进 monsterQueue）。`monsterAttacksQueued=false` 由 `AbstractRoom.endTurn()` 的匿名 Action 设置（该 action 依次 `addToBot(EndTurnAction)`、`WaitAction`、`MonsterStartTurnAction`）。
5. **否则 `!monsterQueue.isEmpty()`** → 取队首：intent != NONE 时 `addToBottom(ShowMoveNameAction(m))` + `IntentFlashAction(m)`；然后 **`m.takeTurn(); m.applyTurnPowers();`**（一帧内同步调完）；队列空 → `WaitAction(1.5F)`。
6. **否则 `turnHasEnded && !monsters.areMonstersBasicallyDead()`** → **新回合启动块**（429–476）：
   - 非 skipMonsterTurn → `monsters.applyEndOfTurnPowers()`（每活怪 `applyEndOfTurnTriggers()` → 玩家所有 power `atEndOfRound()` → 每活怪 power `atEndOfRound()`）；
   - `player.cardsPlayedThisTurn = 0`；`orbsChanneledThisTurn.clear()`；Careless/ControlledChaos 每日 mod 处理；
   - **`player.applyStartOfTurnRelics()`**（stance.atStartOfTurn → relic `atTurnStart` → blight `atTurnStart`）→ **`applyStartOfTurnPreDrawCards()`**（手牌 `atTurnStartPreDraw`）→ **`applyStartOfTurnCards()`**（抽牌堆/手牌/弃牌堆 `atTurnStart`）→ **`player.applyStartOfTurnPowers()`**（power `atStartOfTurn`）→ **`player.applyStartOfTurnOrbs()`**（orb `onStartOfTurn`，金缆线再触发首位 orb）；
   - `turn++`；`skipMonsterTurn=false`；`turnHasEnded=false`；计数清零；
   - **掉格挡**：无 Barricade/Blur power 时，有 Calipers → `loseBlock(15)`，否则 `loseBlock()`（全清）；
   - 若 `!isBattleOver`：`addToBottom(new DrawCardAction(null, gameHandSize, true))` → `applyStartOfTurnPostDrawRelics()` → `applyStartOfTurnPostDrawPowers()` → `addToBottom(new EnableEndTurnButtonAction())`。

### 其他关键方法
- `endTurn()`（204）：`player.resetControllerValues(); turnHasEnded = true; playerHpLastTurn = player.currentHealth;`（由 EndTurnAction 调用）。
- `clearPostCombatActions()`（143）：战斗结束清理 actions，但**保留** `HealAction`、`GainBlockAction`、`UseCardAction` 和 `actionType == DAMAGE` 的动作。
- `callEndTurnEarlySequence()`（493）：Time Eater 类提前结束回合。
- `cleanCardQueue()`（513）：移除手中卡对应的队列项（取消出牌）。
- `clear()`（536）：战斗重置全部状态；**`turn = 1`**。
- `incrementDiscard(endOfTurn)`（565）：静态计数 + 非回合末弃牌时触发 relic `onManualDiscard`。
- `queueExtraCard(card, monster)`（586）：复制卡进 limbo、`purgeOnUse=true`、插队。

### 战斗开始的完整时序（`rooms/AbstractRoom.update()` COMBAT 分支）
`preBattlePrep`（`characters/AbstractPlayer.java:1712`：`actionManager.clear()`、清 orbs/powers、`drawPile.initializeDeck(masterDeck)`、`energy.prep()`、怪物 `usePreBattleAction`）之后，COMBAT 阶段 waitTimer 分支：等待期间有动作就更新；waitTimer 耗尽那帧：`turnHasEnded = true` → BattleStartEffect → `addToBottom(GainEnergyAndEnableControlsAction(energyMaster))`（内 `gainEnergy` → relic/power `onEnergyRecharge`）→ `applyStartOfCombatPreDrawLogic`（relic `atBattleStartPreDraw`）→ `addToBottom(DrawCardAction(gameHandSize))` → `EnableEndTurnButtonAction` → `applyStartOfCombatLogic`（relic/blight `atBattleStart`）→ `applyStartOfTurnRelics/PostDrawRelics/Cards/Powers/Orbs` → `useNextCombatActions()`。

### generateSeeds()（480–494）
**12 个 RNG 全部用同一个 `Settings.seed` 初始化**：
```java
monsterRng = eventRng = merchantRng = cardRng = treasureRng =
relicRng = monsterHpRng = potionRng = aiRng = shuffleRng =
cardRandomRng = miscRng = new Random(Settings.seed);
```
`mapRng` 不在 generateSeeds 里（各幕构造时 `seed + actNum` / `actNum*100` / `actNum*200` / `actNum*300` 生成地图）。

用途：
- `monsterRng`：遭遇选择；`eventRng`：事件滚动；`merchantRng`：商店；`cardRng`：**卡牌奖励与稀有度 roll**（`rollRarity` 1824：`cardRng.random(99) + cardBlizzRandomizer`）；`treasureRng`：宝箱/金币；`relicRng`：遗物 tier；`potionRng`：药水。
- **每层重置**（`nextRoomTransition` 1973–1977）：`monsterHpRng = aiRng = shuffleRng = cardRandomRng = miscRng = new Random(Settings.seed + floorNum);`
- **存档恢复**：`loadSeeds(save)`（496–523）用 `new Random(Settings.seed, save.monster_seed_count)` 恢复 counter；存档只存 7 个计数器（monster/event/merchant/card/treasure/relic/potion）+ ai/shuffle/card_random 等，`monsterHpRng` 等靠 seed+floorNum 恢复。

`dungeonTransitionSetup()`（2901）：切幕时 `actNum++`，并把 cardRng counter 推进到 250/500/750 档位。

### getRewardCards()（1625–1696）
数量 = 3 → relic `changeNumberOfCardsInReward` 可改 → Binary mod -1。每张：`rollRarity()`（房间加成 `getCurrRoom().getCardRarity(roll)`，fallback：<3 RARE / <40 UNCOMMON / 其余 COMMON）；COMMON 时 `cardBlizzRandomizer -= cardBlizzGrowth`（下限 -40），RARE 时重置为 5；PrismaticShard 时 `CardLibrary.getAnyColorCard(rarity)` 否则 `getCard(rarity)`（对应池 `getRandomCard(true)` 且**从池中移除**）；去重循环；最后 `makeCopy()` 成新实例并按 `cardUpgradedChance` 升级（RARE 永不自动升级）。

## 6. closeCurrentScreen 路由与 CurrentScreen 枚举

- CurrentScreen 枚举（23 值）：`NONE, MASTER_DECK_VIEW, SETTINGS, INPUT_SETTINGS, GRID, MAP, FTUE, CHOOSE_ONE, HAND_SELECT, SHOP, COMBAT_REWARD, DISCARD_VIEW, EXHAUST_VIEW, GAME_DECK_VIEW, BOSS_REWARD, DEATH, CARD_REWARD, TRANSFORM, VICTORY, UNLOCK, DOOR_UNLOCK, CREDITS, NO_INTERACT, NEOW_UNLOCK`。
- closeCurrentScreen：`if (previousScreen == screen) previousScreen = null` → 按 screen switch 清理（GRID → 若奖励非空则 `previousScreen = COMBAT_REWARD`；CARD_REWARD → 仅当 `!screenSwap` 才 onClose）→ 尾部路由：`previousScreen == null` → `screen = NONE`；`screenSwap` → 消费标志；否则恢复 previousScreen 并 `openPreviousScreen`（`rewardTime` 时强制 COMBAT_REWARD）。
- `genericScreenOverlayReset()`：`previousScreen == null` 时：玩家已死 → `previousScreen = DEATH`；否则 `isScreenUp = false`。

## 7. nextRoomTransition 流程

1. 复位 proceedButton、`combatRewardScreen.clear()`、清 rewards。
2. 按**当前**房间清理遭遇队列：Elite → `eliteMonsterList.remove(0)`（空则 `generateElites(10)` 补）；Monster → `monsterList` 同理（`generateStrongEnemies(12)`）。
3. 清屏、fadeIn、`resetPlayer()`（清 orbs/hand/powers/drawPile/discardPile/exhaustPile/limbo、loseBlock、回 Neutral stance、turn=1）。
4. **floorNum++**（仅非读档）→ `SaveHelper.saveIfAppropriate(ENTER_ROOM)`。
5. **重建 5 个层 RNG**：`monsterHpRng/aiRng/shuffleRng/cardRandomRng/miscRng = new Random(seed + floorNum)`。
6. **'?' 房间二次解析**：EventRoom 时用 eventRng counter 快照复制 rng → `EventHelper.roll` → 可能替换为 ELITE/MONSTER/SHOP/TREASURE 房（`combatEvent = true`），地图图标仍为 '?'；非读档时 `eventRng = 副本`（先消耗 1 次掷点）。
7. `setCurrMapNode(nextRoom)`；遗物 `justEnteredRoom`；`getCurrRoom().onPlayerEntry()`；玩家摆位；MonsterRoom → `player.preBattlePrep()`。
- `actNum++` 只在 `dungeonTransitionSetup()`（新幕构造时）。
- Boss 层是虚拟节点 `(-1, 15)` 照常 floorNum++；层级切换发生在 boss 房战斗结束后：ProceedButton `goToNextDungeon` → `isDungeonBeaten = true` → CardCrawlGame 检测后 `getDungeon(nextDungeon)` 构造新 dungeon。
- `initializeFirstRoom()`：floorNum++ 后若首房是 MonsterRoom 则又 floorNum--（Neow 后首战不消耗楼层数）。

## 8. 回合钩子调用顺序（含 AbstractPlayer 层）

- **玩家回合开始**：`applyStartOfTurnRelics`（stance.atStartOfTurn → relic.atTurnStart → blight.atTurnStart）→ `applyStartOfTurnPreDrawCards` → `applyStartOfTurnCards` → `applyStartOfTurnPowers` → `applyStartOfTurnOrbs` → 掉格挡 → `DrawCardAction` → `applyStartOfTurnPostDrawRelics` → `applyStartOfTurnPostDrawPowers` → `EnableEndTurnButtonAction`。
- **玩家回合结束**（`AbstractRoom.endTurn()`）：`player.applyEndOfTurnTriggers()`（怪物才有 atEndOfTurnPreEndTurnCards(false) 分支；玩家 `atEndOfTurn(true)`）→ `addToBottom(ClearCardQueueAction)` → `addToBottom(DiscardAtEndOfTurnAction)` → 全牌 `resetAttributes()` → 匿名 action（EndTurnAction + Wait + MonsterStartTurnAction + `monsterAttacksQueued=false`）。
- **怪物回合**：`MonsterStartTurnAction` → `MonsterGroup.applyPreTurnLogic()`（非 Barricade 的怪 `loseBlock()` → `applyStartOfTurnPowers()`）→ `m.takeTurn()` → `m.applyTurnPowers()`（`duringTurn`）。
- **回合交界怪物侧**：`MonsterGroup.applyEndOfTurnPowers()`：活怪 `applyEndOfTurnTriggers` → 玩家 power `atEndOfRound` → 活怪 power `atEndOfRound`。

## 9. 对 Rust 移植的风险点

1. **全局静态状态海量**（AbstractDungeon 约 150+ static 字段、GameActionManager 9 个 static 计数、CardCrawlGame.dungeon 自引用全局）→ Rust 收敛为单一 `GameContext`/`RunState`。
2. **null 语义遍布**（screen 枚举 null、`CardQueueItem.card == null` 有语义、getCurrRoom 早期可为 null）→ Rust 用 Option 显式区分。
3. **一帧多 update 的时序耦合**：动作结束同帧取下一个；`PlayerTurnEffect.update()` 里做 `energy.recharge()`（逻辑塞在 vfx 里）；DrawCardAction 多帧逐张、依赖真实 dt；FAST_MODE 压时长 → Rust 固定逻辑步长。
4. **副作用寄生在构造器**：ApplyPowerAction 构造器改卡费/加毒量；UseCardAction 构造器触发 onUseCard 链；EmptyDeckShuffleAction 构造器 onShuffle → 统一建模为 "on_construct + on_first_tick"。
5. **队列中途改队**：action update 里 addToTop/addToBottom；clearPostCombatActions 遍历间隙清队列；RNG 是顺序敏感资源，调用顺序差异会改变种子流。
6. **越界遍历**：heal/addBlock/brokeBlock 遍历 player.relics 或 monsters 的越界访问。
7. **double 派发与字符串 ID** + instanceof 分支。
8. **数值边界**：格挡上限 999、能量上限 999、maxHealth 下限 1、`lastDamageTaken = min(dmg, currentHealth)`、heal 在 isDying 不生效。
9. **屏幕状态机与转场异步**：fadeTimer 驱动、三重读档标志 → 显式 TransitionState。
