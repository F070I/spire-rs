## 1. AbstractMonster 结构

- `HashMap<Byte, String> moveSet`（基本未用）、`EnemyMoveInfo move`、`ArrayList<Byte> moveHistory`（104）、`byte nextMove = -1`（106）。
- `ArrayList<DamageInfo> damage`（99）——每个招式的基伤列表，takeTurn 按索引取。
- `Intent intent`（111）；`intentDmg/intentBaseDmg/intentMultiAmt/isMultiDmg`。
- `EnemyType type = NORMAL | ELITE | BOSS`；`escaped/escapeNext/cannotEscape`；`ESCAPE=99`、`ROLL=98` 保留字节。
- **Intent 枚举 17 个**：`ATTACK, ATTACK_BUFF, ATTACK_DEBUFF, ATTACK_DEFEND, BUFF, DEBUFF, STRONG_DEBUFF, DEBUG, DEFEND, DEFEND_DEBUFF, DEFEND_BUFF, ESCAPE, MAGIC, NONE, SLEEP, STUN, UNKNOWN`。**没有 STRONG_ATTACK**。

**EnemyMoveInfo**：`byte nextMove; Intent intent; int baseDamage; int multiplier; boolean isMultiDamage;`

**setHp（919-933）——HP 随机化公式**：
```java
currentHealth = AbstractDungeon.monsterHpRng.random(minHp, maxHp);
if (endless && blight ToughEnemies) currentHealth *= mod;
if (ModEnabled("MonsterHunter")) currentHealth *= 1.5f;
maxHealth = currentHealth;
```
ascension 修正不由 setHp 完成，而是每个怪自己在构造器里换区间。

**ascension 固定模式**：构造器选数值档（A_2/A_7/A_8/A_9 等常量）；getMove 里改概率分布（LouseNormal 17 阶）；takeTurn 加效果（Cultist 17 阶仪式 3→4）；usePreBattleAction 加初始 buff（LouseNormal 7/17 阶 CurlUp）。

**damage() 钩子链**（719-827）见记录 03 §5。

## 2. 怪物 AI 模式

**抽象方法**：`public abstract void takeTurn(); protected abstract void getMove(int paramInt);`

**rollMove()（544-546）**：`getMove(AbstractDungeon.aiRng.random(99))` —— getMove 的参数是 aiRng 掷出的 0-99 随机数，与概率阈值比较。`init()`（832）战斗开始即 rollMove 一次决定首回合意图。aiRng 每层重播种。

**setMove 语义**（492-501）：
```java
setMove(String moveName, byte nextMove, Intent intent, int baseDamage, int multiplier, boolean isMultiDamage)
```
- `nextMove`：怪物自定义 byte 招式 ID（同时是 takeTurn switch 的 case）；非 -1 时**立即 append 进 moveHistory**（516）。
- `baseDamage`：意图显示用基伤；-1 非攻击。`createIntent()`（459-482）用 `calculateDamage(baseDamage)` 算 intentDmg。
- `multiplier` + isMultiDamage：xN 次数。

**历史查询**：`lastMove(byte)`、`lastMoveBefore(byte)`、`lastTwoMoves(byte)`。**注意 moveHistory 在 setMove 时就写入**——getMove 内调 lastMove 看到的是"上回合选的招"。移植最易踩的语义点。

## 3. 回合流程中怪物侧的调用顺序

玩家点结束回合后：
1. `callEndOfTurnActions()` → phase 进入怪物回合。
2. GameActionManager 394-397：`monsterAttacksQueued=true`；`monsters.queueMonsters()`。
3. `MonsterGroup.queueMonsters()`（161-166）：**按 monsters 列表顺序**（站位从左到右）把活着的（或 halfDead）怪塞进 monsterQueue。
4. 每帧消费 queue（399-427）：ShowMoveNameAction + IntentFlashAction → **`m.takeTurn(); m.applyTurnPowers();`**。
5. 队列空 → `WaitAction(1.5s)`，然后 429-471：`monsters.applyEndOfTurnPowers()` → 玩家新回合系列 → `turn++`。

**新回合开始**：`MonsterStartTurnAction` → `monsters.applyPreTurnLogic()`（MonsterGroup:128-133：非 Barricade 的怪 `loseBlock()`，然后 `applyStartOfTurnPowers()`）。每个怪 takeTurn 结尾都 `addToBottom(new RollMoveAction(this))`。

**意图伤害何时算**：`AbstractMonster.applyPowers()`（1324-1344）对 damage 里每个 DamageInfo 调 `dmg.applyPowers(this, player)`；`calculateDamage`（1274-1322）顺序：怪物自身 powers atDamageGive → 玩家 powers atDamageReceive → player.stance.atDamageReceive → 背击 ×1.5 → 怪物 atDamageFinalGive → 玩家 atDamageFinalReceive → floor 钳 0。怪被打/被上 debuff 后由相应 Action 调 applyPowers() 刷新意图数字。初次显示：init() → rollMove → Room enter 时 `monsters.init()` + `showIntent()`。

**targeting**：单目标攻击几乎全部硬编码 AbstractDungeon.player。

## 4. 特殊机制逐条

- **The Guardian**：三态 changeState 切换。开放态受击累计 dmgTaken（重写 damage() 281-301），≥阈值（30/35/40，每次防御模式 +10）→ ChangeStateAction("Defensive Mode")：移除 ModeShift、+20 格挡、setMove(CLOSE_UP) 并立即 createIntent()；关闭态打完 twin slam → Offensive Mode 重挂 ModeShift。招式链靠各 useXxx() 末尾 setMove 下一招硬写。
- **Hexaghost**：6 个 HexaghostOrb；orbActiveCount 决定 getMove 查表（0=Sear,1=Tackle,2=Sear,3=Inflame,4=Tackle,5=Sear,6=Inferno，224-251）。Sear 打完后点亮一颗，6 颗全亮强制 Inferno（286）。Activate 时伤害 = `player.currentHealth/12+1`×6（takeTurn 动态改 damage.get(2).base 再 applyPowers()）。
- **SlimeBoss**：SplitPower + 重写 damage()：血量≤50% 且 nextMove!=3 时强制 setMove(SPLIT)；split 回合 CannotLoseAction → SuicideAction(self,false) → SpawnMonsterAction 两个大液（继承当前血量）→ CanLoseAction。
- **Time Eater**：本体不管卡牌数，usePreBattleAction 挂 TimeWarpPower（power 侧数玩家每 12 张牌强制结束回合）；半血一次性 Haste（清 debuff + 回满血，169-173）。
- **The Heart**：usePreBattleAction 挂 InvinciblePower(300/200) 与 BeatOfDeathPower(1/2)；首手必 Debilitate(3)（塞 5 状态牌 + 3 维 debuff）；getMove 按 moveCount%3 轮转攻击/攻击/强化(4)，强化按 buffCount 递进 Artifact→BeatOfDeath→PainfulStabs→Str10→Str50（177-199）；4 阶起 BloodShot 12→15 次 ×2。
- **Awakened One**：一阶段 form1；重写 damage()：血≤0 且 !halfDead 时设 halfDead=true、触发 onDeath 链、清牌队列、剥离 debuff、**强制 setMove(REBIRTH) 并 createIntent/applyPowers**；changeState("REBIRTH") 重置 maxHealth（300/320）→ HealAction(满血) + CanLoseAction，form1=false。战斗开始 cannotLose=true。死亡时随行 Cultist EscapeAction。
- **Donu & Deca**：isAttacking 布尔交替招式（Deca 初始 true，Donu 初始 false）。Deca 防御给全体 16 格挡；Donu 防御给全体 3 力量（19 阶 Artifact 3/其余 2）。双方 die() 都要 areMonstersBasicallyDead。
- **Reptomancer**：usePreBattleAction 给同组非自身怪挂 MinionPower；daggers[4] 槽位，召唤回合 SpawnMonsterAction(new SnakeDagger(...)) 补空槽；A18 起每次补 2 把。die() 时场上其余怪 SuicideAction。
- **Nemesis**：每回合结束若没有 Intangible 就挂 IntangiblePower(1)；镰刀 45 伤有 scytheCooldown=2 回合冷却；重写 damage() 先把 Intangible 下伤害截为 1（双保险）。
- **Giant Head**：count=5 每回合 getMove 里 count--，倒数；count≤1 后每次 setMove(IT_IS_TIME, dmg = startingDeathDmg - count*5)（伤害 +5/回合无限涨，预生成 8 档 DamageInfo，index>7 截断）；A18 倒数起点 4。自带 SlowPower。
- **Transient**：HP 999，每回合伤害 +10（7 档 + count 递增）；FadingPower(5/6) 倒数到 1 时 SuicideAction 自爆（算胜利）。
- **Darkling**：组内 3 只；任一只被打到 0 血：halfDead=true、清 powers、若还有活 Darkling → 强制 setMove(COUNT=4 UNKNOWN)（下回合 REINCARNATE=5：回半血复活 + RegrowPower + 遗物 onSpawnMonster）；3 只全 halfDead → cannotLose=false 并对全体 m.die()。usePreBattleAction 设 cannotLose=true。
- **Spire Growth**（ID="Serpent"）：ConstrictedPower 挂玩家（source=这条蛇）；A17 强制每 2 回合必缠。
- **Snecko**：首手必 Glare = 给玩家 ConfusionPower（费用随机化）。

## 5. 怪物死亡 / 逃跑 / 掉落

## 7. RNG 一览（移植要分层）

- `monsterRng`：遭遇队列（整个 run 一条流，存档恢复带 counter）。
- `monsterHpRng / aiRng / miscRng`：**每层重播种** `new Random(seed + floorNum)`。
- `treasureRng`：战后金币。
- Gremlin/Shape 抽取用 miscRng；Louse 血量上限里 biteDamage 用 `monsterHpRng.random(5,7)`（伤害也吃这条流！LouseNormal.java:54-59）；Reptomancer HP 在构造参数直接 `monsterHpRng.random(180,190)`。
- 动画/语音用 MathUtils.random（非种子，可忽略）。

## 8. MonsterGroup 与行动顺序

`monsters/MonsterGroup.java`：`ArrayList<AbstractMonster> monsters` 保序 = 站位（MonsterHelper.getEncounter 传入数组顺序即从左到右）。行动顺序 = 列表顺序。运行时插入：`addMonster(index, m)` 精确插位、`addSpawnedMonster`（add 到 index 0，SpawnMonsterAction 实际用它，所以召唤物先行动）、`add`（尾部）。死亡判定：`areMonstersDead`（isDead||escaped 全真）、`areMonstersBasicallyDead`（isDying||isEscaping 全真）。`getRandomMonster(exception, aliveOnly, rng)` 有带种子/不带种子两个版本。

## 9. Rust 移植风险点

1. **无接口的"状态机多态"**：怪物状态散落私有 boolean（isOpen/firstTurn/halfDead/form1/roared/usedHaste/numTurns/turnCount/scytheCooldown...）+ `changeState(String)` 字符串 switch → Rust 每怪一个 enum State + match；changeState 会被 Action 间接调用（ChangeStateAction 持怪物引用异步执行）。
2. **moveHistory 写入时机陷阱**：setMove 内 append → lastMove 语义是"本回合之前刚设的招"。
3. **意图伤害是快照**：intentDmg 缓存，靠外部 Action 刷新；HexaghostActivate 就地改 damage.get(i).base。
4. **异步 Action 队列**：die() 内 addToTop、AwakenedOne.damage() 内 setMove+createIntent+applyPowers 同步混排。
5. **继承字段横向依赖**：halfDead 在 AbstractCreature 层；cannotLose 在 Room 层。
6. **字符串键**：changeState("Defensive Mode")、power ID → enum 常量表。
7. **种子随机分层**：miscRng/monsterHpRng/aiRng 三条流每层重播种，Reptomancer 在构造参数掷 HP —— 顺序敏感。
8. **渲染耦合**：updateDeathAnimation 内含 endBattle 触发（战斗结束判定在渲染帧里！）→ 移到逻辑 tick。
