## 1. random/Random.java（完整逐行理解）

**文件**：`random/Random.java`（123 行）。

- **内部算法**：包一层 libgdx 的 `com.badlogic.gdx.math.RandomXS128`（xorshift128+ 变体；seed 经 murmurHash3 混淆生成初始 state `(seed0, seed1)`）。
- **字段**：`public int counter = 0`。所有 public 方法**进入即 `counter++`**（先自增再取数）。
- **构造**：
  - `Random()`：`this(MathUtils.random(9999L), MathUtils.random(99))`（调试用）。
  - `Random(Long seed)`：`new RandomXS128(seed)`。
  - `Random(Long seed, int counter)`：**快进实现 = 循环调用 `random(999)` counter 次**。
- **public 方法全集**（每个都 counter++）：
  | 方法 | 行为 |
  |---|---|
  | `copy()` | 用 random.getState(0/1) 复制 128 位状态 + counter |
  | `setCounter(int target)` | 仅当 `counter < target` 时用 **`randomBoolean()`**（不是 random(999)）补到目标；否则打印 ERROR |
  | `int random(int range)` | `nextInt(range + 1)` → **含两端 [0, range]** |
  | `int random(int start, int end)` | `start + nextInt(end - start + 1)` |
  | `long random(long range)` | `(long)(nextDouble() * range)` |
  | `long random(long start, long end)` | `start + (long)(nextDouble() * (end - start))` |
  | `long randomLong()` | `nextLong()` |
  | `boolean randomBoolean()` | `nextBoolean()` |
  | `boolean randomBoolean(float chance)` | `nextFloat() < chance` |
  | `float random()` | `nextFloat()` |
  | `float random(float range)` | `nextFloat() * range` |
  | `float random(float start, float end)` | `start + nextFloat() * (end - start)` |

- **种子体系**：12 个 RNG（monsterRng/eventRng/merchantRng/cardRng/treasureRng/relicRng/monsterHpRng/potionRng/aiRng/shuffleRng/cardRandomRng/miscRng）**全部用同一个 Settings.seed new 出来**，仅靠各自 counter 区分；读档 loadSeeds(save) 用 `new Random(seed, save.xxx_seed_count)` 快进恢复，另恢复 cardBlizzRandomizer。
- 进幕切换 dungeonTransitionSetup() 把 cardRng counter 对齐到 250/500/750 档位。
- **双 RNG 系统**：`java.util.Random`（LCG）也被用于洗牌（relic 池、ModHelper.setTodaysMods、deck 洗牌用 `shuffleRng.randomLong()` 播种的 java.util.Random）——Rust 需同时实现 JDK LCG。

## 3. 解锁系统

### 3.1 UnlockTracker
- Prefs 文件：`STSUnlocks`（解锁状态）、`STSUnlockProgress`、`STSSeenCards`、`STSSeenRelics`、`STSSeenBosses`、`STSAchievements`、`STSBetaCardPreference`。
- **解锁状态编码**：0=锁定，**1="已见到待确认"**，**2=已解锁**。`hardUnlock(key)`：仅当值==1 时置 2；`hardUnlockOverride(key)`：无条件置 2。
- `lockedCards/lockedRelics/lockedCharacters`：refresh() 重建（写死 27 张卡 + 3 角色 + 21 遗物的初始锁定名单）。
- **解锁顺序**：`getUnlockBundle(c, unlockLevel)` 每级 3 件，**先卡后遗物交替**（每角色 5 级 = 15 件）。Ironclad：L0 卡(Heavy Blade/Spot Weakness/Limit Break) → L1 遗物(Omamori/Prayer Wheel/Shovel) → L2 卡(Wild Strike/Evolve/Immolate) → L3 卡(Havoc/Sentinel/Exhume) → L4 遗物(Blue Candle/Dead Branch/Singing Bowl)。
- **解锁进度（score 机制）**：prefs 键 `{CLASS}UnlockLevel / {CLASS}Progress / {CLASS}CurrentCost / {CLASS}TotalScore / {CLASS}HighScore`。`addScore`：progress += score，>=CurrentCost 则 UnlockLevel+1、cost 走 `incrementUnlockRamp`（300→750→1000→1500→2000→2500→3000→3000…，其他 +250，封顶 3000/4000）。等级 5 封顶。
- **角色解锁条件**（DeathScreen.java:604-676）：
  1. **The Silent**：任意一次死亡/胜利结算（首次进入结算屏）时解锁。
  2. **Defect**：用 Silent 通关结算时解锁。
  3. **Watcher**：`willWatcherUnlock()`（DeathScreen.java:547）：Defect 已解锁 且 (RUBY 或 EMERALD 或 SAPPHIRE 成就已达成)。
- **进阶解锁**：`isAscensionUnlocked(p)`（UnlockTracker.java:807）：该角色 victory>0 即解锁进阶。**升级**：`isAscensionMode && !seedSet && !isTrial && level<20 && 正在玩最高级` → incrementAscension。

## 11. Rust 移植风险点

1. **RandomXS128 语义必须逐位复刻**：murmurHash3 setSeed、nextLong 唯一核心、nextInt(n)=nextLong(n)、nextBoolean=next(1)。`Random(seed, counter)` 快进用 random(999)，`setCounter` 用 randomBoolean()——**两种快进消耗序列不同**。
2. **双 RNG 系统**：JDK LCG 也要实现。
3. **seed/counter 的恢复链**：12 个同 seed RNG + 各自 counter + card_random_seed_randomizer + 250/500/750 对齐。
4. **序列化兼容**：SaveFile 是 Gson 大 JSON + XOR("key") + Base64；字段缺省语义遍布读档代码。
5. **静态全局状态** → 显式传入上下文。
6. **反编译噪声**：Watcher 专属卡 bundle 引用 ForesightUnlock/NovaUnlock 需与卡池实际 ID 核对；unlock/cards/* 全是空标记类，真正逻辑在 UnlockTracker.getUnlockBundle 的 switch 里。
7. **平台耦合点**：Gdx.files.local（路径）、publisherIntegration、TimeHelper（离线需本地 UTC）、AsyncSaver 线程模型。
8. **mod 双通道**：daily mods 走 ModHelper.isModEnabled，CustomMode 的非每日 mod（Endless/The Ending/Blight Chests）走 AbstractPlayer.customMods.contains(...)——两条链都要移植。
9. **成就/解锁的 retroactive 逻辑**：UnlockLevel/CurrentCost 的 ramp 表（300→750→1000→1500→2000→2500→3000→3000→4000，默认 +250）必须一致。
