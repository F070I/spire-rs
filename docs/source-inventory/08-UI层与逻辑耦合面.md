# 盘点原始记录 08：UI ↔ 游戏逻辑耦合面（screens/ + ui/ + 输入 + 主循环）

> 路径均相对 `src/main/java/com/megacrit/cardcrawl/`。阶段 0 原始盘点记录。
> 标注【逻辑】= 必须移植的游戏逻辑；【纯渲染】= 可丢弃/重做。

## 0. 总览：架构结论

- **主循环是单线程帧循环**：`core/CardCrawlGame.java`（libgdx ApplicationListener）→ render() 里先 update() 再绘制。输入是**全局静态鼠标状态机**（`helpers/input/InputHelper.java`），每帧 updateFirst() 采样、updateLast() 清除一帧标志。
- **Screen 是"有状态的交互页"而非纯 View**：`AbstractDungeon.CurrentScreen`（24 个枚举值，AbstractDungeon.java:299）驱动 switch 分发，每个 Screen 的 update() 里混有选卡校验、扣钱、入牌组、记录 metrics 等副作用。
- **Screen 路由是隐式状态机**：closeCurrentScreen() + previousScreen + screenSwap 决定"关掉后回到哪"。
- 奖励链：room.rewards → CombatRewardScreen.setupItemReward() 拷贝并追加卡牌奖励 → 点击 RewardItem → claimReward()。

## 2. 玩家战斗中全部交互输入类型

1. **悬停查看手牌/怪物**；2. **打牌—点击拖拽**（拖入出牌区）；3. **打牌—无目标卡**：拖到出牌区松手 → canUse(this,null) 通过→playCard()；不通过→气泡 cantUseMessage；4. **打牌—指定目标**：松手后进入单目标模式（瞄准箭头），点怪→canUse(p, hoveredMonster)→playCard；右键取消；键盘左右切目标；5. **打牌—对全体**：ALL_ENEMY/ALL 走无目标分支；6. **热键 1~9/0**：`InputHelper.getCardSelectedByHotkey(hand)`；7. **键盘模式**：updateFullKeyboardCardSelection()；8. **X 费卡能量分配**：没有 UI 分配步骤——useCard() 里 energyOnUse **自动钳制为当前能量**；9. **拖拽取消**：右键/拖到屏幕底部；10. **结束回合**：EndTurnButton 点击或 endTurn 键；手牌无可出卡时按钮发光；11. **药水**：PotionPopUp 上半【使用】（canUse 门控；targetRequired 则进 targetMode 点怪），下半【丢弃】（canDiscard）；药水栏满收药水时 claimReward 返回 false→红色闪烁；12. **查看牌堆**：DrawPilePanel/DiscardPilePanel/ExhaustPanel 点击或热键；13. **遗物查看**：顶栏遗物条（>8 个翻页）；14. **顶栏信息**：HP/金币/药水/爬升等级 tip；15. **帮助/关键词**：卡牌 hover 时 renderCardTip → TipHelper.renderTipForCard(card, keywords)；16. **设置**：Esc→settingsScreen（TopPanel 有完整的"当前屏×Esc"路由表）；17. **Peek**：选卡/奖励界面里按住回看战斗手牌与房间。

`InputActionSet` 完整动作清单（helpers/input/InputActionSet.java）：confirm, cancel, topPanel, proceed, settings, map, masterDeck, drawPile, discardPile, exhaustPile, endTurn, peek, up/down/left/right, releaseCard, selectCard_1..10 —— 官方快捷键协议。

## 4. AbstractDungeon 主循环与调用链

### 4.1 CardCrawlGame
- `GameMode`（:184）：`SPLASH → CHAR_SELECT → GAMEPLAY ⇄ DUNGEON_TRANSITION`。
- **update() 帧序（:587）**：cursor → screenShake → updateFade → music → **InputHelper.updateFirst()** → cardPopup/relicPopup → 按 mode 分发 → debug 键 → **InputHelper.updateLast()**（清一帧标志）。
- `startOver` 淡出后重置（updateFade():426）：AbstractDungeon.reset()、ShopScreen.resetPurgeCost()、settings/trial/seed 全清、重建 MainMenuScreen、mode=CHAR_SELECT。
- `loadPostCombat()`（:772）：从存档重建 room.rewards（RewardSave 类型：CARD/GOLD/RELIC/POTION/STOLEN_GOLD/SAPPHIRE_KEY/EMERALD_KEY）与 smoked/mugged 标志。

### 4.2 AbstractDungeon.update()（:2365）
```
playtime 累加 → screenTimer 门控点击 → topPanel.update() → dynamicBanner.update()
→ currMapNode.room.updateObjects()
→ switch (screen):                    // 每帧只更新当前屏
    NONE/NO_INTERACT: dungeonMapScreen.update() + currMapNode.room.update() + scene.update() + room.eventControllerInput()
    MAP / GRID / CARD_REWARD / COMBAT_REWARD / HAND_SELECT / SHOP / DEATH / VICTORY / SETTINGS /
    MASTER_DECK_VIEW / GAME_DECK_VIEW / DISCARD_VIEW / EXHAUST_VIEW / BOSS_REWARD / UNLOCK / NEOW_UNLOCK / CREDITS / FTUE / DOOR_UNLOCK: 各屏 update()
→ topLevelEffects/effectsQueue 更新
→ overlayMenu.update()                // 内含 player.hand.update()、EndTurnButton、能量、遗物
```

### 4.3 AbstractRoom.update()（rooms/AbstractRoom.java:225，战斗阶段）
```
EVENT: event.updateDialog()
COMBAT:
  monsters.update()
  战斗开场序列(waitTimer): actionManager 跑完起始动作→GainEnergyAndEnableControls→DrawCard(gameHandSize)
                           →EnableEndTurnButton→showCombatPanels→applyStartOfCombat*/StartOfTurn* 一串钩子
  正常阶段: 若 !isScreenUp → actionManager.update(); 玩家存活→ player.updateInput()   // ← 手牌交互入口
            player.combatUpdate(); player.isEndingTurn → endTurn()
  战斗结束(isBattleOver): 等动作清空→phase=COMPLETE→掉落奖励→MonsterRoomBoss 特殊处理
```
注意 `updateInput()` 只在 `!isScreenUp` 时执行——有屏打开时手牌输入被冻结。

### 4.4 奖励展示链
`AbstractDungeon.getRewardCards()`（:1625）→ 房间 rewards 里的 RewardItem(CARD) 持有 → 战斗结束→CombatRewardScreen.open()/openCombat() → setupItemReward() 拷贝 room.rewards **并追加卡牌 RewardItem** → 点击卡牌奖励→RewardItem.claimReward() 返回 false 并打开 CardRewardScreen.open(cards, this, ...)，previousScreen = COMBAT_REWARD → 选卡/跳过后 takeReward() 把该 RewardItem 从 rewards 移除并重排；closeCurrentScreen 的 CARD_REWARD 分支里若 rItem != null 则 previousScreen = COMBAT_REWARD 返回奖励页。

## 5. 手牌交互细节

- **canUse 在 UI 层的用法**：出牌判定点全部在 clickAndDragCards()/updateSingleTargetInput() 里调 hoveredCard.canUse(this, monster)；失败→ThoughtBubble(cantUseMessage)。按钮层：EndTurnButton 的 glow 用 card.isGlowing 与 hand.canUseAnyCard()。
- **目标选择模式**：拖拽 + 松手；点击拖拽控制；键盘模式（左右选卡、confirm 拿起、ENEMY 卡自动进入单目标、键盘切目标）；取消 = 右键 / 拖到屏幕底部 / releaseCard()。
- **手牌重排**：vanilla 无手动重排，顺序=摸牌顺序。refreshHandLayout()（CardGroup.java:215）按当前牌序排 target_x。
- **手牌上限**：`Settings.MAX_HAND_SIZE = 10`；DrawCardAction 按 `gameHandSize - hand.size()` 摸，**手牌可被效果加到超过 10**；回合结束才统一 DiscardAtEndOfTurnAction。

## 6. TipHelper / 关键词 / 卡牌文本协议（文字 UI 的核心资产）

- **Keyword 源**：`localization/KeywordStrings.java`（每语言 JSON → Keyword{NAMES[], DESCRIPTION}）→ `helpers/GameDictionary.java`（:66 initialize）建 `TreeMap<String,String> keywords`（词→描述）与 `parentWord`（别名→主词），并预置 `[R]/[G]/[B]/[W]/[E]` 五个能量键。
- **文本标记协议**（解析在 `helpers/FontHelper.java`）：
  - **renderSmartText（:921）按空格分词**：`"NL"`=换行、`"TAB"`=5 空格；
  - `[E]/[R]/[G]/[B]/[W]` = 能量球图标；另有 `[C]`卡/`[P]`药水/`[T]`遗物/`[S]`特殊图标；
  - `#r/#g/#b/#y/#p` = 红/绿/蓝/金/紫，**只作用于紧随的那一个词**（identifyColor :1214，`word.substring(2)` 去前缀）；
  - 动态着色 helper：`FontHelper.colorString(text, "y")`；
  - 卡牌描述本体在 AbstractCard.rawDescription → initializeDescription() 拆成 DescriptionLine（含 [E] 宽度占位）；
  - 中文/日文走 Settings.lineBreakViaCharacter 分支（逐字符换行）。
  - **给文字 UI 的启示**：协议 = 空格分词 + NL/TAB + [X] 图标 + #x 单词着色；移植时把它变成 AST（段落/图标/样式 span）而不是在渲染器里二次解析。

## 9. Rust 移植风险点

1. **UI 层直接写游戏状态**：ShopScreen.purchaseCard/purgeCard（扣金、入牌组、补货）、SingingBowlButton.onClick（+2 maxHp、删奖励）、RewardItem.claimReward、HandCardSelectScreen 的 transform 调用、PotionPopUp 的 destroyPotion——移植必须抽成"意图事件 → 核心处理"。
2. **VFX 承担副作用**：FastCardObtainEffect（入牌组）、Campfire*Effect（回血/升级/删卡）是"动画对象里改状态"——操作即时结算，effect 只做演出。
3. **全局可变单例网**：InputHelper.*、AbstractDungeon.*、CardCrawlGame.mode、EnergyPanel.totalCount（static!）、Settings.* → 单一 World + 帧序明确的 update(input_events)。
4. **一帧标志协议**：justClickedLeft/scrolledDown 等在 updateLast() 统一清除——事件必须在帧内排队消费；跨帧状态（isDraggingCard、clickDragTimer）变成显式状态机。
5. **Screen 返回栈隐式规则**：previousScreen/screenSwap + 特例（GRID 关→若有奖励回 COMBAT_REWARD；CARD_REWARD 关→rItem!=null 回 COMBAT_REWARD；MAP 的 dismissable 决定能否 cancel；TopPanel 里 13 种"当前屏×Esc"路由表）→ 实现 `enum Screen + Option<Screen> return_to`。
6. **文本协议内嵌渲染**：NL/TAB/[E]/#r 分词解析在 FontHelper 两个分支里 → 先做独立 parse_description() -> Vec<Span> 再考虑换行。
7. **关键词高亮来源**：card.keywords 由 initializeDescription 扫 GameDictionary 生成；本地化 JSON 的 NAMES 是数组（多别名）——中文界面关键词匹配规则（无空格分词）与英文完全不同。
8. **Deprecated/死代码**：CardRewardScreen 的 discoveryOpen/codexOpen 等标 @Deprecated；CurrentScreen.CHOOSE_ONE/TRANSFORM 枚举基本闲置（chooseOne 复用 CARD_REWARD 屏）——以实际被调用的 open()/customCombatOpen()/chooseOneOpen()/draftOpen() 为准。
9. **RNG 边界**：UI 侧也会掷随机（商店价格抖动、促销卡）——随机数调用点全部归入核心。
10. **Metrics 混入 UI**：recordMetrics/addShopPurchaseData 散布在点击处理里 → 核心在对应事件统一记账。
11. **控制器/触屏分支噪音**：可整体不移植，但要确认没有夹带逻辑。
12. **时序门控**：screenTimer（进战斗 2s 禁点击）、FAST_MODE 改 ACTION_DUR_* 常量、waitTimer 战斗开场序列——回合开始/结束的动作队列顺序是语义的一部分。
