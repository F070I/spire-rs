# 盘点原始记录 05：地图生成 / 地下城流程 / 房间系统 / Neow

> 路径均相对 `src/main/java/com/megacrit/cardcrawl/`。阶段 0 原始盘点记录。

## 1. MapGenerator 算法完整描述

### 1.1 常量与调用方
- `dungeons/AbstractDungeon.java` L202-205：`MAP_HEIGHT = 15`、`MAP_WIDTH = 7`、`MAP_DENSITY = 6`、`FINAL_ACT_MAP_HEIGHT = 3`。
- 唯一调用点 `AbstractDungeon.generateMap()`（L607-643）：`map = MapGenerator.generateDungeon(15, 7, 6, mapRng)`。三幕同参数；`TheEnding` 不调用，用自建固定图 `generateSpecialMap()`（TheEnding.java L71-166）。
- `mapRng` 每幕重建：Exordium `seed + actNum`；TheCity `seed + actNum*100`；TheBeyond `seed + actNum*200`；TheEnding `seed + actNum*300`（固定图未用）。读档用 `seed + saveFile.act_num[×100/×200/×300]` 重建。

### 1.2 路径生成（createPaths，MapGenerator.java L74-88）
- `row_size = width - 1 = 6`；循环 `pathDensity`(=6) 次，每次 `startingNode = randRange(rng, 0, 6)`。
- 第 0 条路径记录 `firstStartingNode`；**第 1 条路径（i==1）重摇直到 ≠ firstStartingNode**；第 2~5 条无起点限制。
- 每条路径从虚拟边 `MapEdge(startingNode, -1, startingNode, 0)` 开始，调用递归 `_createPaths`（L162-243）。

### 1.3 _createPaths 递归规则
1. **终点**：若 dstY+1 >= nodes.size()（y=14 顶行），加一条 `isBoss=true` 的边（指向虚拟 Boss 位置 (3,16)），排序后返回（L167-171）。
2. **步进方向**：x=0 时偏移 ∈ [0,1]；x=6 时 ∈ [-1,0]；其余 ∈ [-1,1]。`newEdgeX = dstX + randRange(min,max)`，`newEdgeY = dstY+1`。
3. **交叉/过早合并抑制（祖先检查，L187-218）**：候选目标已有父节点时，对每个 `parent != currentNode` 求 `getCommonAncestor(parent, currentNode, 5)`（L136-160）。`ancestor_gap = newEdgeY - ancestor.y`：gap < 3 时按相对方位重摇 newEdgeX；**gap ∈ {3,4} 落入空 `else if (>=5)` 分支，允许合并**。
4. **同行防交叉（L219-236）**：左侧相邻节点 (x-1) 若有边，其"最右边"边（getMaxEdge）的 dstX 若 > newEdgeX 则抬到该值；右侧对称。
5. 加边（addEdge 按 compareTo 去重）→ 排序 → targetNode.addParent(currentNode) → 递归。

### 1.4 randRange 与随机源
- L312-318：`randRange(rng,min,max) = rng.random(max-min)+min`。
- 随机源 `random/Random.java`：包装 libgdx `RandomXS128`（xorshift128+），带 counter；`random(int range)` = `nextInt(range+1)`（双闭区间）。`Collections.shuffle(roomList, rng.random)` 直接把 RandomXS128 当 java.util.Random 用。

### 1.5 生成后处理与校验
- `filterRedundantEdgesFromRow`：**只处理第 0 行**，删除与之前节点目的地相同的重复边。
- `lastMinuteNodeChecker`（RoomTypeAssigner L123-136）：有边但无房间的节点 → MonsterRoom。
- **没有连通性验证**。`passesDonutCheck`（AbstractDungeon L710-755）是死代码。

### 1.6 房间类型分配
`AbstractDungeon.generateMap()`（L607-643）：
1. `count` = 所有 `hasEdges() && y != map.size()-2`（**y==13，倒数第二行不计入配额**——复现种子的关键怪癖）的节点数。
2. `generateRoomTypes(roomList, count)`（L662-697）：shopCount/restCount/treasureCount/eventCount = round(count × 各 chance)；`eliteCount`：BigGameHunter ×2.5、**进阶 ≥1 时 ×1.6**；monsterCount = 余数（隐式）。房间池只放 Shop/Rest/Elite/Event（treasureRoomChance 三幕均 0.0）。
3. 硬性指定行：`assignRowAsRoomType(map.get(14), RestRoom)`（顶行全篝火）、`map.get(0)` 全 MonsterRoom、`map.get(8)` 全 TreasureRoom（Endless + MimicInfestation 时改 MonsterRoomElite，L629-633）。
4. `distributeRoomsAcrossMap(mapRng, map, roomList)`（RoomTypeAssigner L153-175）：`Collections.shuffle(roomList, rng.random)` 后 `assignRoomsToNodes`（L138-151）按**行序 y=0→14、x=0→6** 为无房节点取第一个满足规则的房间（从池中 remove）。

规则函数（RoomTypeAssigner）：
- `ruleAssignableToRow`（L93-103）：RestRoom 与 MonsterRoomElite **禁入 y≤4**；RestRoom **禁入 y≥13**。
- `ruleParentMatches`（L80-91）：Rest/Treasure/Shop/Elite 不得与任何父节点同类型。
- `ruleSiblingMatches`（L68-78）：Rest/Monster/Event/Elite/Shop 不得与"同父兄弟节点"同类型。
- `getNextRoomTypeAccordingToRules`（L105-121）：取池中第一个通过三规则的房间；**y==0 时无视 parent/sibling 规则直接采用**。
5. `setEmeraldElite()`（L645-660）：若最终幕可用且未持绿钥匙，用 `mapRng.random(0, eliteNodes.size()-1)` 随机选一个精英节点设 `hasEmeraldKey = true`。

## 2. MapRoomNode / MapEdge 结构

- MapRoomNode：`int x, y`；`ArrayList<MapEdge> edges`；`ArrayList<MapRoomNode> parents`；`AbstractRoom room`；`boolean taken, highlighted, hasEmeraldKey`。方法：`hasEdges()`；`addEdge`（按 compareTo 去重）；`isConnectedTo`；`wingedIsConnectedTo`；`getEdgeConnectedTo`；`leftNodeAvailable/centerNodeAvailable/rightNodeAvailable`（按 dstX 与 x 比较，L144-175）。
- MapEdge：`public final int srcX, srcY, dstX, dstY`（**逻辑仅用这四个 int**）；`taken`、`color`、`dots`（纯渲染）。`compareTo`：先 dstX 再 dstY；`markAsTaken()`。
- **"MapRoomType 枚举"不存在**。房间类型由具体类 + `AbstractRoom.RoomType` 枚举（SHOP, MONSTER, SHRINE, TREASURE, EVENT, BOSS，基本闲置）+ 地图符号字符串 `"M"/"E"/"B"/"?"/"$"/"T"/"R"`（map/Legend.java L43-82）表示。

## 3. 玩家选路

- **isConnectedTo**（MapRoomNode L104-113）：遍历自身 edges。
- **首行限定**：`MapRoomNode.update()` L289-314：`!firstRoomChosen && this.y == 0 && currRoom.phase == COMPLETE` 时可点击首行节点（**该分支不做 isConnectedTo 检查**）。选中后 animWaitTimer 0.25s → `setCurrMapNode(this)`（首房）或 `currMapNode.taken = true`、对应边 markAsTaken、`AbstractDungeon.nextRoom = this`、nextRoomTransitionStart()。
- **Wing Boots**（wingedIsConnectedTo，L115-127）：只要 `node.y == edge.dstY`（同排任一节点）且 WingBoots counter > 0 即"连通"；点击时 counter--，归零后 setCounter(-2)。
- **Boss 节点**：不在 map 数组内。`map/DungeonMap.java` L62-95：`currRoom.phase == COMPLETE && screen == MAP && (isDebug || currMapNode.y == 14 || (TheEnding && y == 2))` 时 bossHb 可点击；点击 → markAsTaken、创建虚拟节点 `new MapRoomNode(-1, 15)`、`room = new MonsterRoomBoss()`、`nextRoom = node`、nextRoomTransitionStart()。

## 4. 楼层推进完整链

```
点击地图节点 (animWaitTimer 0.25s)
  → AbstractDungeon.nextRoomTransitionStart()   [L1860-1867]
      fadeOut(); waitingOnFadeOut = true; Terminal 模组扣 1 HP
  → updateFading() 等待渐黑 (L2645-2666)
  → nextRoomTransition(SaveFile)                [L1911-2049]
```

`nextRoomTransition` 顺序：
1. 清 combatRewardScreen、清 nextRoom.room.rewards。
2. 按**当前**房间消耗遭遇队列（Elite → eliteMonsterList.remove(0)；Monster → monsterList）。
3. 清屏、fadeIn、`resetPlayer()`（清手牌/牌堆/力场/格挡，回中立姿态，turn=1）。
4. **floorNum++**（非读档）、指标、`SaveHelper.saveIfAppropriate(ENTER_ROOM)`。
5. **每层重掷 RNG**：monsterHpRng/aiRng/shuffleRng/cardRandomRng/miscRng = new Random(seed + floorNum)。
6. **'?' 房间二次解析**（L1993-2007）：EventRoom 用 eventRng counter 快照复制 rng → EventHelper.roll() 掷实际房间类型（EVENT/ELITE/MONSTER/SHOP/TREASURE，含 Tiny Chest 强制宝箱、Juzu Bracelet 怪→事件、MimicInfestation 宝箱→精英），generateRoom(roomType) 替换房间；战斗房标 combatEvent=true；地图仍 '?'。非读档时 eventRng = 副本（先消耗 1 次掷点）。
7. `setCurrMapNode(nextRoom)`；遗物 justEnteredRoom；`getCurrRoom().onPlayerEntry()`；玩家摆位；MonsterRoom → `player.preBattlePrep()`。

**floorNum / actNum 变化时机**：actNum++ 只在 dungeonTransitionSetup()（新幕构造）：cardRng counter 档位对齐（0-250→250、250-500→500、500-750→750）、清列表、回血（进阶≥5 回 75% 缺失量，否则满血）、进阶 6/10/14 效果。Boss 层虚拟节点 (-1,15) 照常 floorNum++。

## 5. 每种房间的完整流程

### MonsterRoom
- 构造：phase = COMBAT，symbol "M"。onPlayerEntry：`monsters = CardCrawlGame.dungeon.getMonsterForRoomCreation()`（取 monsterList.get(0)）→ monsters.init()；waitTimer = 0.1。
- 战斗→奖励：`isBattleOver && actions.isEmpty()` 时 0.25s 后 phase = COMPLETE → 掉落链：普通怪 `addGoldToRewards(treasureRng.random(10,20))` → `dropReward()` → `addPotionToRewards()` → `combatRewardScreen.open()` → 存 POST_COMBAT 档。
- 药水概率（addPotionToRewards L644-669）：基础 40% + `blizzardPotionMod`（初始 0，失败 +10 / 成功 -10）；`rewards.size() >= 4` 时 0%；White Beast 100%。

### MonsterRoomElite
- symbol "E"，eliteTrigger = true，卡牌稀有度基础 10/40。金币 25-35（treasureRng）。
- `dropReward`（L79-90）：`returnRandomRelicTier`（relicRng 0-99：<50 common，>82 rare，否则 uncommon；BigGameHunter +10）→ addRelicToRewards；BlackStar → 追加 `addNoncampRelicToRewards`（排除 Peace Pipe/Shovel/Girya）；`addEmeraldKey`。
- `applyEmeraldEliteBuff`（L34-66）：带绿钥匙的精英入场 `mapRng.random(0,3)` 四选一 buff：力量 +actNum+1 / MaxHP +25% / 金属化 2*actNum+2 / 再生 1+2*actNum。

### MonsterRoomBoss
- symbol "B"；onPlayerEntry：`monsters = dungeon.getBoss()`（bossKey，置 atBoss = true）；path_taken 加 "BOSS"；bossList.remove(0)；`getCardRarity` 恒 RARE。
- Boss 金币 100 + miscRng.random(-5,5)（进阶 13 ×0.75）；CursedRun 送诅咒。**Beyond/Ending 的 Boss 不给卡/药奖励**。
- Boss 胜利后走向（ProceedButton）：Beyond → 进阶 20 且 bossList 剩 2 时 `goToDoubleBoss()`，否则 `goToVictoryRoomOrTheDoor()`（虚拟节点 (-1,15) 放 VictoryRoom(HEART)）；Ending → `goToTrueVictoryRoom()`（(3,4) TrueVictoryRoom）；其余 → `goToTreasureRoom()`（虚拟节点 (-1,15) 放 TreasureRoomBoss）。

### TreasureRoom
- symbol "T"，phase=COMPLETE。onPlayerEntry：`chest = AbstractDungeon.getRandomChest()`（L595-604：treasureRng 0-99，<50 SmallChest、<83 MediumChest、否则 LargeChest）。
- `AbstractChest.open(false)`：randomizeReward（treasureRng 一掷决定金币与遗物稀有度）→ 金币 GOLD_AMT ± 10% → 遗物入奖励 → **`isFinalActAvailable && !hasSapphireKey` 时追加 addSapphireKey** → combatRewardScreen.open()。
- 箱型参数：SmallChest 75/25/0 稀有度、金币 50% / 25；MediumChest 35/50/15、35% / 50；LargeChest 0/75/25、50% / 75。

### TreasureRoomBoss
- 构造即设 `CardCrawlGame.nextDungeon`；phase=COMPLETE（无 Blight Chests mod 时）。
- `chest = new BossChest()`（3 张 returnRandomRelic(BOSS)，构造时已消耗 bossRelicPool 前 3 个）。
- `open(true)` → `bossRelicScreen.open(relics)` 三选一（BossRelicSelectScreen：特殊替换遗物 Black Blood/Ring of the Serpent/FrozenCore/HolyWater `instantObtain` 0 号槽）；可跳过。
- **本版本 BossChest 不掉蓝钥匙**（蓝钥匙在普通宝箱）。
- 离开：goToNextDungeon：未选遗物则 `noPick()` 记 metric。

### RestRoom / CampfireUI
- symbol "R"，phase=INCOMPLETE。onPlayerEntry：循环播放篝火音效、`new CampfireUI()`、遗物 onEnterRestRoom。
- **选项注册**（CampfireUI.initializeButtons L91-128）：固定 `RestOption(true)` + `SmithOption(有可升级卡且非 Midas)`；然后**每个遗物调用 `addCampfireOption(buttons)`**：Shovel→DigOption、Girya→LiftOption(counter<3)、PeacePipe→TokeOption(有可移除卡)；`canUseCampfireOption` 可禁用；`isFinalActAvailable && !hasRubyKey` 时追加 RecallOption。全部不可用 → 直接 phase = COMPLETE。
- 点击 → useOption() + somethingSelected=true；实际效果由 Campfire*Effect 触发（Rest 回 30%、Smith 升级、Dig 挖遗物、Lift +1 力、Toke 移除卡、Recall 红钥匙）。
- **Recall（红钥匙）**：CampfireRecallEffect → 清空当前房奖励、ObtainKeyEffect(RED)、phase = COMPLETE。

### ShopRoom
- symbol "$"，phase=COMPLETE，`shopRarityBonus = 6`，baseRareCardChance=9。onPlayerEntry：playBGM、proceed 按钮改标签、`new Merchant()`（商品由 merchantRng 驱动）。
- `updatePurge`：gridSelectScreen 选卡完成 → ShopScreen.purgeCard() + masterDeck 移除 + purgeAvailable = false。

### EventRoom
- symbol "?"，phase=EVENT。onPlayerEntry（L20-25）：`eventRngDuplicate = new Random(seed, eventRng.counter)`（快照复制）→ `event = AbstractDungeon.generateEvent(eventRngDuplicate)` → event.onEnterRoom()。
- **事件选取 `AbstractDungeon.generateEvent`**（L2097-2113）：`rng.random(1.0f) >= shrineChance(0.25f)`（75%）→ 先 getEvent（事件），池空再 getShrine；否则先神龛，最后兜底事件。
- **事件池定义**：各幕 initializeEventList：Exordium 11 个（L237-249）、TheCity 13 个（L220-233）、TheBeyond 7 个（L208-216）；shrineList 三幕相同 6 个；specialOneTimeEventList 全局 14 个（L1541-1559）。
- **去重 = 池消耗制**：getEvent（L2259-2357）带条件过滤（Dead Adventurer/Mushrooms 需 floorNum>6；MoaiHead 需无 Golden Idol 且 HP>50%；Cleric 金≥35；Beggar 金≥75；Colosseum 需 currMapNode.y > map.size()/2），命中后 `eventList.remove(key)`——同一事件整局只出现一次（跨幕不重置，dungeonTransitionSetup 会 eventList.clear() 重新初始化）。

### Heart 房与真结局
- `VictoryRoom`：`EventType {HEART, NONE}`；phase=EVENT；HEART → SpireHeart 事件房。入口：Beyond Boss 胜利后。
- `TrueVictoryRoom`：phase=INCOMPLETE，结局动画；入口：Ending Boss 胜利后（节点 (3,4)）。
- `EmptyRoom`：phase=COMPLETE，空，用于 Neow 前/读档虚拟节点 (0,-1)。

## 6. NeowReward

- `NeowRewardType`（L51-71）共 19 值：`RANDOM_COLORLESS_2, THREE_CARDS, ONE_RANDOM_RARE_CARD, REMOVE_CARD, UPGRADE_CARD, RANDOM_COLORLESS, TRANSFORM_CARD, THREE_SMALL_POTIONS, RANDOM_COMMON_RELIC, TEN_PERCENT_HP_BONUS, HUNDRED_GOLD, THREE_ENEMY_KILL, REMOVE_TWO, TRANSFORM_TWO_CARDS, ONE_RARE_RELIC, THREE_RARE_CARDS, TWO_FIFTY_GOLD, TWENTY_PERCENT_HP_BONUS, BOSS_RELIC`。
- `NeowRewardDrawback`：`NONE, TEN_PERCENT_HP_LOSS, NO_GOLD, CURSE, PERCENT_DAMAGE`。

**生成逻辑（四选一）**：`NeowEvent.blessing()`（L448-468）：`rng = new Random(Settings.seed)`（**每次重置**，counter 从 0 开始）→ 依次 `new NeowReward(0..3)` 四类各随机出一个：
- **cat0 换牌**：THREE_CARDS / ONE_RANDOM_RARE_CARD / REMOVE_CARD / UPGRADE_CARD / TRANSFORM_CARD / RANDOM_COLORLESS —— 6 选 1。
- **cat1 增益**：THREE_SMALL_POTIONS / RANDOM_COMMON_RELIC / TEN_PERCENT_HP_BONUS / THREE_ENEMY_KILL / HUNDRED_GOLD —— 5 选 1。
- **cat2 代价**：先均匀抽 drawback（4 选 1：-10% MaxHP / 清空金币 / 加诅咒 / 损失 30% 当前血 `currentHealth/10*3`）；选项池 = RANDOM_COLORLESS_2 + ONE_RARE_RELIC + THREE_RARE_CARDS + TRANSFORM_TWO_CARDS 恒在；REMOVE_TWO 在 CURSE 时排除；TWO_FIFTY_GOLD 在 NO_GOLD 时排除；TWENTY_PERCENT_HP_BONUS 在 TEN_PERCENT_HP_LOSS 时排除。
- **cat3**：唯一选项 **BOSS_RELIC**。

首局（`bossCount == 0`，playerPref `"{Class}_SPIRITS"`）走 `miniBlessing()`（L433-446）：两个固定选项 THREE_ENEMY_KILL（Neow's Lament）与 TEN_PERCENT_HP_BONUS。

**效果实现要点**（activate，L228-331）：
- 先执行 drawback（CURSE 走延迟 `cursed` 标记）。
- 卡牌选择类打开 gridSelectScreen，在 update() 里应用：upgrade / masterDeck.removeCard / AbstractDungeon.transformCard(c, false, NeowEvent.rng)。
- 抽卡：`getRewardCards(rareOnly)`（L359-393）与 `rollRarity()`（rng.randomBoolean(0.33f) → UNCOMMON 否则 COMMON；rareOnly 全 RARE）；ONE_RANDOM_RARE_CARD 直接 getCard(RARE, NeowEvent.rng)。
- THREE_SMALL_POTIONS：3 个 PotionHelper.getRandomPotion() 进 combatRewardScreen 并**移除其中的卡奖励**（L298-321）。
- **换 Boss 遗物（BOSS_RELIC）**：`player.loseRelic(player.relics.get(0).relicId)` —— **移除玩家遗物列表第 0 个（初始遗物）**，然后 returnRandomRelic(BOSS)。cat3 恒定出现。
- 收尾 metricData；waitingToSave → POST_NEOW 存档。

**NeowRoom**：Exordium 构造器（L65-77）在 floorNum==0 时把 currMapNode = (0,-1) 挂 NeowRoom(false)。NeowEvent.buttonEffect 状态机（screenNum）：0/1 → blessing/miniBlessing；2 → 选项 0=blessing 1=openMap；3 → activate；10 → dailyBlessing()（每日 mod：Heirloom/Allstar/Specialized/SealedDeck/Draft）；999 → endlessBlight()；99/默认 → openMap()。

## 7. Act 4（TheEnding）触发条件与三钥匙

- **解锁前提** `Settings.isFinalActAvailable`（core/Settings.java L671）：铁甲/猎手/机器人**三个角色都通关**且非 daily/trial，或自定义模式 finalActAvailable。
- **Ruby 红钥匙**：篝火"回忆"（RecallOption → ObtainKeyEffect(RED)）。
- **Emerald 绿钥匙**：setEmeraldElite() 随机标记精英节点 → 击败该精英（先吃 applyEmeraldEliteBuff）→ EMERALD_KEY RewardItem。
- **Sapphire 蓝钥匙**：**普通宝箱开启时掉落**（AbstractChest.open L118-123，链接到遗物奖励；拾取遗物即连带拿钥匙——relicLink 处理）。BossChest 不给。
- **进入 TheEnding**：Beyond Boss 胜利 → VictoryRoom(HEART) → SpireHeart 事件（L187）：`isFinalActAvailable && hasRubyKey && hasEmeraldKey && hasSapphireKey` → 开门 → getDungeon("TheEnding")；否则普通胜利。
- TheEnding 地图（generateSpecialMap L71-166）：5 行 × 7 列固定图，只有 x=3 列有内容：`RestRoom(y0) → ShopRoom(y1) → MonsterRoomElite(y2) → MonsterRoomBoss(y3, "The Heart") → TrueVictoryRoom(y4)`。

## 9. AbstractRoom.phase 与 isBattleOver

- `RoomPhase`（rooms/AbstractRoom.java L103-108）：`COMBAT, EVENT, COMPLETE, INCOMPLETE`。
- **isBattleOver 判定**：`endBattle()`（L456-499）置 isBattleOver = true、endBattleTimer = 0.25f；COMBAT 更新分支 L295：`if (isBattleOver && actionManager.actions.isEmpty())` → 0.25s → phase = COMPLETE + 结算奖励。
- `isBattleEnding()`（L695-703）= isBattleOver || monsters.areMonstersBasicallyDead()。

## 10. Rust 移植风险点

1. **RNG 语义必须精确**：RandomXS128 + counter；Boss 列表 shuffle 用 `new java.util.Random(rng.randomLong())`（java LCG）；Collections.shuffle 复用 RandomXS128——Rust 需同时实现 xorshift128+ 与 java.util.Random 及 JDK shuffle。
2. **Neow rng 每次重置**：counter 恒从 0 开始——同局内多次 Neow（Endless）序列相同，移植不能"顺手修复"。
3. **静态全局海** → 单一 Dungeon 资源。
4. **反编译伪影/疑似原版 bug，需保真**：MapGenerator.getCommonAncestor 的 `node1.x < node2.y`（应为 node2.x，L142）；_createPaths 祖先检查修改 newEdgeX 后不中断 parent 循环；ancestor_gap ∈ {3,4} 落入空分支；MapEdge.compareTo 的 `assert false` 尾支；endBattle 的 attackCount 统计循环 L468-480 在第一个 ATTACK 处 break（计数永远 ≤1）。
5. **种子复现敏感点**：房间分配依赖 shuffle 后线性扫描顺序 + 行/列遍历序；count 排除 y==13 行；filterRedundantEdgesFromRow 仅首行；monsterList 相邻去重重试（i--）消耗额外 monsterRng；EventRoom counter 快照复制双段消耗。
6. **未播种随机**：MapRoomNode.offsetX/offsetY 不影响逻辑 → 隔离"逻辑 RNG"与"表现 RNG"。
7. **虚拟节点坐标越界**：Boss (-1,15)、Boss 边指向 (3,16)、Neow (0,-1) → 数据结构容忍越界坐标。
8. **房间类型无枚举**：靠类 + mapSymbol 字符串；'?' 房间会在进入时替换 room 对象。
9. **逻辑与渲染耦合**：setCurrMapNode 里 SoulGroup 转移、CampfireUI 静态 hidden、AbstractRoom.waitTimer 静态。
10. **死代码/陷阱**：passesDonutCheck 未调用；getCardFromPool 的 switch 故意贯穿（RARE→UNCOMMON→…回退链）；TreasureRoomBoss.getNextDungeonName 的 Endless 循环回 Exordium。
