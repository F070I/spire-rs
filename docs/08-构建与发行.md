# 阶段 0 交付物 8：跨平台构建与发行规范

> 从架构设计起内置 Windows / macOS 支持；平台支持不是开发结束后的临时移植。

## 1. 目标平台

| 平台 | 目标三元组 | 产物 | 优先级 |
|---|---|---|---|
| Windows x86_64 | `x86_64-pc-windows-msvc`（或 gnu，见 §3） | `sts.exe` 独立运行 | P0 |
| macOS Intel | `x86_64-apple-darwin` | 原生可执行 `sts` | P1 |
| macOS Apple Silicon | `aarch64-apple-darwin` | 原生可执行 `sts` | P2（架构设计兼容，保留构建能力） |

## 2. 跨平台硬约束（架构层，冻结）

1. **sts-core / sts-data / sts-interface 零平台 API**：不 import 任何平台 crate；标准库以外仅白名单依赖（docs/03 §2）。
2. 终端差异统一收敛在 sts-terminal 的 `term` 模块：
   - raw mode / 事件：`crossterm`（Windows 用 ConPTY/VT，Unix 用 termios——库内处理）。
   - 颜色：ANSI/VT 转义；检测 `TERM`/`NO_COLOR`/`CLICOLOR` 降级。
   - 编码：输出 UTF-8；Windows 下启动时 `SetConsoleOutputCP(65001)` 由 crossterm 处理或显式调用其公开 API；禁用内嵌 platform cfg 到核心。
   - 屏幕刷新：全帧重绘 + 可选差分（不引入 ncurses 等重依赖）。
3. 文件路径：存档目录按平台约定（见 §5），统一经 `dirs`-style 函数实现（自行实现，避免额外依赖，或引入 `dirs` 白名单——实现时二选一并记录）。
4. 时间：每日种子用本地 UTC 日（与原版 TimeHelper 语义对齐，见 docs/07 Q-05）。

## 3. 构建配置（Cargo）

workspace `Cargo.toml`：

```toml
[profile.release]
opt-level = 3
lto = "fat"
codegen-units = 1
strip = true        # 符号剥离，直接收益体积
panic = "abort"     # 游戏无需展开；注意：禁用 catch_unwind 路径
```

发行命令（可重复，写入 `scripts/`）：

```powershell
# Windows x86_64（本机）
cargo build --release -p sts-terminal --target x86_64-pc-windows-msvc
# 产物：target/x86_64-pc-windows-msvc/release/sts.exe
```

```bash
# macOS（在 macOS 机器或 CI 上）
rustup target add x86_64-apple-darwin aarch64-apple-darwin
cargo build --release -p sts-terminal --target x86_64-apple-darwin
cargo build --release -p sts-terminal --target aarch64-apple-darwin
# 可选 universal binary：
lipo -create target/x86_64-apple-darwin/release/sts \
     target/aarch64-apple-darwin/release/sts -output sts-universal
```

说明：
- Windows 选择 msvc（链接系统 CRT；如需完全免安装独立，可在发行记录中评估 `-C target-feature=+crt-static` 静态 CRT，属构建参数实测项）。
- 交叉编译 macOS 从 Windows 不可行（osxcross 不在范围）；macOS 构建在 macOS 环境执行。ARM64 版本在阶段 6 只要求"可构建"，实测项标注。

## 4. 体积目标与测量

- 目标：**每个平台的实际发行产物 < 20 MB**（测 `sts.exe` / `sts` 文件本身，不含源码/压缩包）。
- 测量记录（写入 `docs/release-notes.md`）：目标三元组、rustc 版本、构建参数、产物字节数、`cargo tree` 依赖摘要。
- 预算控制：核心逻辑与数据全为 Rust 常量表/代码（预计 < 8 MB 未压缩依赖总量）；风险来自 serde+crossterm（合计通常 < 3 MB stripped）。若超标：先查依赖树（`cargo bloat`），再谈参数。
- 禁止用删功能换体积（docs 总规范 §9）。

## 5. 存档与用户数据路径（跨平台）

| 平台 | 目录（与原版语义等价的本地化选择） | 说明 |
|---|---|---|
| Windows | `%APPDATA%\StsText\saves`（回退 `%LOCALAPPDATA%`） | 需要目录创建与权限检查 |
| macOS | `~/Library/Application Support/StsText/saves` | 首次运行创建；权限拒绝时给出可读错误 |
| 兼容模式 | 可执行文件旁 `saves/`（`--portable` 参数） | 便于 U 盘/便携使用与测试 |

存档写盘策略沿用原版安全写法（复制旧档 → 校验 → 写新档 → 校验，见记录 07 §2.4），同步实现（不需要原版的异步线程）。

## 7. 打包

- Windows：单文件 `sts.exe`（可再提供 zip）。
- macOS：先提供单文件 `sts`；`.app` 封装（Info.plist、图标）按需后置，不阻塞发行。
- 均不安装运行时依赖（Rust 静态链接业务代码；CRT 策略见 §3 说明）。
